# 整体架构

------

# 1. 项目简介

**Nexus Admin** 是一个基于微内核（Microkernel）架构的**插件化系统拓展平台**，秉持"插件即业务，拓展即能力"的设计理念，支持系统能力的灵活替换与无限扩展。

系统采用严格微内核模型构建：

- 内核是唯一稳定运行时
- 所有系统能力均以插件形式提供
- 技术框架不进入核心
- 能力可替换：任何系统能力均可通过新插件平滑替代

平台目标：

- **极小核心**：核心保持稳定、长期演进
- **能力外置**：所有可变能力插件化
- **强隔离**：插件之间无直接耦合
- **可替换性**：任何能力可被新插件替代

------

# 2. 总体架构概览

## 2.1 模块总览

```text
backend/
├─ nexus-admin-core/        # 微内核运行时与插件物理加载实现
├─ nexus-admin-api/         # 业务基础层，提供拓展点定义、内建能力实现与 RESTful API
├─ nexus-admin-app/         # 启动装配层，负责系统装配、框架适配与平台级配置
└─ plugins/                 # 插件实现集合
```

------

## 2.2 架构核心原则

1. Core 是系统唯一不可插件化模块
2. 所有系统能力必须通过 ExtensionPoint 抽象
3. 插件是唯一能力实现形式
4. 插件之间不得直接依赖
5. 技术框架不得进入核心
6. 核心负责能力调度，插件负责能力实现

------

# 3. 模块职责说明

------

## 3.1 nexus-admin-core

### 3.1.1 核心定位

> 微内核模块。是系统运行时内核、能力调度中心与插件物理加载实现层。

该模块承担：

- 插件生命周期管理
- 插件依赖解析
- 插件状态管理
- 拓展点注册中心运行时实现
- 运行时事件总线
- 插件调度能力
- 能力选择与替换机制
- 插件目录扫描
- 插件 jar 加载
- 描述文件解析
- 类加载器隔离
- 实例化插件主类

它是整个系统的唯一稳定运行时。

------

### 3.1.2 语义边界

nexus-admin-core：

- 不包含任何技术框架
- 不依赖 Spring / Web / ORM / AI SDK
- 不包含具体能力实现
- 不定义具体业务 SPI 接口
- 通过 4 个独立 Runtime（EventBusRuntime、ExtensionRuntime、ConfigRuntime、PluginRuntime）提供零框架依赖的默认组件装配
- 通过 4 个 Facade（EventBusFacade、ExtensionFacade、ConfigFacade、PluginFacade）隔离 PluginManager 与底层组件
- 通过 CoreConfig 封装运行时配置（RuntimeMode、pluginsDataRoot），避免构造函数参数膨胀

它只负责：

插件运行时管理、能力调度机制、物理加载实现与核心组件装配。

------

### 3.1.3 核心目录结构

```text
nexus-admin-core/
└── core/
    ├── plugin          # 插件生命周期管理
    ├── extension       # 扩展点注册中心
    ├── event           # 事件总线
    ├── config          # 配置中心
    ├── runtime         # 运行时装配（4 个独立 Runtime）
    └── facade          # 门面层（4 个独立 Facade）
```

详见 [插件系统](插件系统.md)、[拓展点系统](拓展点系统.md)、[事件系统](事件系统.md)、[配置中心](配置中心.md)。

------

### 3.1.4 核心能力模型

Core 模块根目录定义平台顶层契约：

| 组件 | 职责 | 详细说明 |
|------|------|----------|
| Plugin | 插件生命周期接口 | 定义插件与平台的交互契约，详见 [插件生命周期](插件生命周期.md) |
| PluginManager | 插件管理器 | 协调插件发现、解析、加载、启动、停止、卸载全流程，详见 [插件系统](插件系统.md) |

在此基础上，Core 模块由四大子系统构成：

| 子系统 | 职责 | 详细说明 |
|--------|------|----------|
| 插件子系统 | 插件扫描、类加载器隔离、描述文件解析、状态迁移管理 | 详见 [插件系统](插件系统.md) |
| 拓展注册中心 | 拓展点实现注册、查询、能力选择与运行时替换 | 详见 [拓展点系统](拓展点系统.md) |
| 事件总线 | 插件间解耦通信与事件分发 | 详见 [事件系统](事件系统.md) |
| 配置中心 | 统一配置读写、Schema 管理、多来源合并 | 详见 [配置中心](配置中心.md) |

每个子系统通过独立的 Runtime（Builder 模式零框架装配）和 Facade（聚合入口）对外暴露，使 Core 模块可脱离 Spring 独立使用。

------

## 3.2 nexus-admin-api

### 3.2.1 核心定位

> 业务基础层（毛坯房）。为平台提供内建的管理能力，是插件依赖的核心 API 模块。

该模块承担：

- **拓展点接口定义**：定义各类系统能力接口（如认证、存储、AI、日志、权限、路由、缓存、Web 等），供插件实现
- **内建能力实现**：提供平台级别的内建业务实现，包括引导认证、管理面板 RESTful API、插件管理等功能
- **通用工具类**：提供插件开发所需的通用类（如 Result、DataResult 等统一响应体）
- **领域视图对象**：定义与前端交互的 DTO 视图层

不包含：

- 核心运行时逻辑（由 core 负责）
- 平台级配置定义（由 app 负责）
- Web 框架适配实现（由 app 负责）
- 系统启动装配逻辑（由 app 负责）

它是插件开发的"唯一依赖模块"，也是平台内建能力的"毛坯房"。

------

### 3.2.2 语义边界

nexus-admin-api：

- 依赖 core（使用其定义的 Plugin、ExtensionPoint 等核心抽象）
- 不依赖 app
- 包含拓展点接口定义
- 包含内建业务实现（鉴权、管理面板 API 等）
- 不参与核心运行时调度（由 core 负责）

它定义并提供：

- 平台拥有哪些能力接口
- 平台内建的管理能力实现
- 插件开发所需的通用工具和 API

------

### 3.2.3 API 目录结构

```text
nexus-admin-api/
└── api/
    ├── extension        # 拓展点接口定义（认证、存储、AI、日志、权限、路由、缓存、Web 等）
    ├── auth             # 内建鉴权实现
    ├── controller       # RESTful API 控制器
    ├── service          # 业务服务层
    ├── config           # Spring 自动配置（Runtime 桥接层 + 功能域装配）
    ├── domain           # 领域视图对象（DTO）
    ├── context          # 调用上下文
    └── exception        # 业务异常处理
```

**API 层配置类说明**：

api 模块的配置类分为两类：

| 类别 | 职责 |
|------|------|
| Runtime 桥接层 | 将 Core 模块 4 个独立 Runtime 装配的组件委托到 Spring 容器，每个 Runtime 对应一个 AutoConfig |
| 功能域装配 | 按功能域划分的 API 层基础设施装配（认证、权限、插件 UI、Web MVC、OpenAPI），每个功能域一个 AutoConfig |

所有 Bean 均带 `@ConditionalOnMissingBean` 保护，app 层可通过声明同类型 Bean 覆盖任意组件。

------

### 3.2.4 设计原则

- 拓展点接口语义稳定，版本向后兼容
- 内建实现遵循拓展点契约，可被插件替代
- 通用工具类简洁、安全、易用
- 不包含平台级配置（配置归属 app 模块）
- 不包含 Web 框架适配实现（适配归属 app 模块）

------

## 3.3 plugins

### 3.3.1 核心定位

> 能力实现模块。是包含所有系统能力的实现集合。

插件：

- 依赖 nexus-admin-api 的能力接口与开发 API
- 不得依赖 nexus-admin-core（仅通过接口交互）
- 不得修改核心

------

### 3.3.2 插件标准结构

#### 插件 jar 结构

```text
storage-plugin.jar
│
├── META-INF/plugin.json
└── com.example.storage
      └── S3StoragePlugin.class
```

------

#### plugin.json 示例

```json
{
  "id": "s3-storage",
  "version": "1.0.0",
  "mainClass": "com.example.storage.S3StoragePlugin",
  "dependencies": {}
}
```

字段说明：

| 字段         | 说明         |
| ------------ | ------------ |
| id           | 插件唯一标识 |
| version      | 插件版本     |
| mainClass    | 插件主类     |
| dependencies | 依赖插件 ID  |

------

## 3.4 nexus-admin-app

### 3.4.1 核心定位

> 启动装配层。负责系统装配、初始化与框架适配。

职责：

- 创建核心运行环境
- 初始化 PluginManager、Registry
- 指定插件目录，启动插件加载流程
- 管理平台级配置（PlatformProperties：平台信息、插件运行时参数）
- 提供 Web 框架适配实现（Spring Web 桥接：SpringWebEndpointExtension 等）
- 监听插件生命周期事件

不包含核心运行时逻辑和业务能力实现。

------

### 3.4.2 核心目录结构

```text
nexus-admin-app/
└── app/
    ├── config            # 装配配置与平台级配置属性
    ├── web               # Web 框架适配实现
    ├── listener          # 插件生命周期监听器
    └── controller        # 平台级控制器
```

------

# 4. 模块依赖关系

## 4.1 依赖方向图

```text
nexus-admin-app
    └── 依赖 → nexus-admin-api

nexus-admin-api
    └── 依赖 → nexus-admin-core

plugins
    └── 依赖 → nexus-admin-api
```

依赖说明：

- **app** 仅依赖 api，通过 api 传递获得 core 的能力，是唯一的装配入口
- **api** 依赖 core，使用其定义的 Plugin、ExtensionPoint 等核心抽象
- **插件** 仅依赖 api，通过 api 中的拓展点接口与平台交互
- core 不依赖任何上层模块，保持零框架依赖
- 依赖链：core ← api ← app

------

## 4.2 严格约束

禁止：

- 插件之间直接依赖
- app 直接依赖 core（应通过 api 传递获得 core 能力）
- core 依赖 api（保持核心零框架依赖）
- core 依赖技术框架
- api 依赖 app（避免循环依赖）
- 拓展点接口依赖运行时实现

------

# 5. 系统能力模型

所有能力通过 nexus-admin-api 中的拓展点接口定义。

定义了一个后台管理系统所需的基本能力，包括：

- 认证能力
- 权限能力
- 存储能力
- 缓存能力
- 日志能力
- AI 能力（详见 [AI 体系](AI体系.md)）
- 路由能力
- 事件能力

核心只负责调度，不提供实现。

------

# 6. 成熟微内核可扩展能力

| -------------- | ---------------------------- |
| 热加载         | 支持运行时加载/卸载插件      |

| 能力优先级仲裁 | 多实现选择策略               |
| 插件健康检查   | 运行时状态监控               |
| 插件资源隔离   | ClassLoader 级隔离           |
| 分布式插件同步 | 集群环境能力同步             |

------

# 7. 架构演进能力

该架构天然支持：

- 能力替换
- 能力扩展
- 插件新增
- 插件删除
- 技术栈迁移
- AI 能力持续演进
- 企业能力沉淀
- 插件商业化

无需修改核心。

------

# 8. 如果持续进化，它会变成什么？

如果该系统持续演进，它将成为：

## 8.1 平台型产品

一个可承载多能力、多团队协作的运行时平台。

------

## 8.2 插件市场型系统

支持：

- 插件发布
- 插件版本管理
- 插件在线安装
- 插件付费分发

------

## 8.3 企业内部能力容器

企业可以：

- 将认证、存储、日志、AI 等能力模块化
- 独立升级
- 独立替换
- 形成内部能力资产库

------

# 9. 最终架构本质

它本质上是：

> 一个 Java 运行时微内核平台。

而不是传统后端系统。

它是：

- 插件运行时
- 能力调度中心
- 企业能力容器
- 可演进架构核心

核心保持稳定，能力持续进化。

这是一种长期主义架构模型。
