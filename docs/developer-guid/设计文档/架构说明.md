# 架构说明

> 这是一个**模块化、插件化、AI 原生的通用后台管理系统扩展平台**。
>
> 设计目标：
>
> - 核心稳定、可长期演进
> - 系统能力可被插件替换 / 重写
> - 面向 AI 原生应用（对话 / RAG / MCP / Agent）
> - 不绑定具体技术实现

------

## 1. 总体架构概览

### 1.1 模块总览

```text
backend-platform/
├─ platform-core/        # 内核 + SPI（领域与扩展点）
├─ platform-plugin/      # 插件 API + 插件运行时
├─ platform-infra/       # 基础设施与技术适配层
├─ platform-app/         # Spring Boot 启动器
└─ plugins/              # 插件实现（业务 / AI / 系统能力）
```

### 1.2 架构核心原则

1. **Core 永远不依赖具体技术**
2. **所有“可变实现”必须可插件化**
3. **系统能力 = Core 定义 + Infra 捕获 + Plugin 实现**
4. **AI 能力视为一等公民，而非附加功能**

------

## 2. platform-core（内核模块）

### 2.1 职责说明

platform-core 是整个系统的“宪法层”，只负责：

- 定义稳定领域模型
- 定义系统能力的抽象接口（SPI）
- 编排核心流程
- 发布领域事件

❗ 禁止内容：

- 不得依赖 Spring / MyBatis / Redis / AI SDK
- 不得出现任何具体实现逻辑

------

### 2.2 目录结构

```text
platform-core/
└─ src/main/java/com/yourorg/platform/core/
   ├─ domain/        # 核心领域模型
   ├─ spi/           # 系统扩展点（最重要）
   ├─ service/       # 核心流程编排
   ├─ event/         # 领域事件
   ├─ context/       # 运行上下文
   └─ exception/     # 核心异常
```

------

### 2.3 核心系统领域（示例）

- 用户（User）
- 角色（Role）
- 权限（Permission）
- 部门 / 岗位
- 字典（Dictionary）

这些领域只描述**规则与关系**，不关心如何存储。

------

### 2.4 核心 SPI 示例

```text
spi/
├─ auth/        # 认证与鉴权
├─ permission/  # 权限解析
├─ routing/     # 路由控制
├─ storage/     # 持久化抽象
├─ cache/       # 缓存抽象
├─ ai/          # AI 能力抽象
└─ log/         # 日志系统抽象（见第 6 章）
```

------

## 3. platform-plugin（插件系统）

### 3.1 职责说明

platform-plugin 负责：

- 插件生命周期管理
- 插件加载与卸载
- SPI 实现注册
- 插件上下文隔离

------

### 3.2 目录结构

```text
platform-plugin/
└─ src/main/java/com/yourorg/platform/plugin/
   ├─ descriptor/    # plugin.yml 解析
   ├─ lifecycle/     # Plugin 接口
   ├─ loader/        # 插件加载器
   ├─ registry/      # SPI 注册中心
   ├─ context/       # PluginContext
   └─ exception/
```

------

### 3.3 插件基本规范

- 插件以 Jar 形式存在
- 必须声明 plugin.yml
- 只能通过 SPI 与 Core 交互

示例 plugin.yml：

```yaml
id: rbac-auth-plugin
version: 1.0.0
provides:
  - auth-provider
  - permission-resolver
```

------

## 4. platform-infra（基础设施模块）

### 4.1 核心定位（非常重要）

> **Infra = 技术世界 → Core 世界的桥梁**

infra 的唯一职责是：

- 捕获技术层事件
- 适配外部框架
- 调用 core 的 SPI

infra 不具备业务语义，也不是系统功能模块。

------

### 4.2 典型 Infra 子模块

```text
platform-infra/
├─ web/           # Web 框架适配（Spring MVC / WebFlux）
├─ security/      # 安全框架适配
├─ persistence/   # ORM / 数据源适配
├─ cache/         # Redis / Caffeine 适配
├─ ai/            # AI SDK 适配（LLM / RAG / MCP）
└─ logging/       # 日志捕获与桥接（见第 6 章）
```

------

## 5. platform-app（启动器）

### 5.1 职责说明

platform-app 是一个**极薄的装配模块**：

- Spring Boot 启动
- 启动插件系统
- 加载默认插件
- 组合 core + infra + plugin

------

### 5.2 结构示例

```text
platform-app/
└─ src/main/java/com/yourorg/platform/app/
   ├─ Application.java
   └─ config/
```

------

## 6. 日志系统设计（新增）

### 6.1 日志系统定位

> **日志是系统级能力，而不是单一模块**

日志系统由三部分组成：

1. Core：定义日志语义与扩展点
2. Infra：捕获事件并生成日志
3. Plugin：决定日志如何存储、分析、展示

------

### 6.2 platform-core 中的日志设计

#### 6.2.1 日志领域模型

```text
platform-core/domain/log/
├─ LogEntry.java
├─ LogType.java        # SYSTEM / AUDIT / AI / TECH
├─ LogLevel.java
└─ LogContext.java     # user / tenant / trace / aiSession
```

#### 6.2.2 日志 SPI

```text
platform-core/spi/log/
├─ LogWriter.java
├─ LogQueryProvider.java
└─ LogRetentionPolicy.java
```

Core 只负责调用 `LogWriter`，不关心实现。

------

### 6.3 platform-infra 中的日志职责

infra 负责：

- 拦截 HTTP 请求
- 捕获鉴权 / 路由 / AI 调用事件
- 转换为 LogEntry
- 调用 LogWriter SPI

```text
platform-infra/logging/
├─ interceptor/
│  ├─ HttpAccessInterceptor.java
│  ├─ AuthDecisionInterceptor.java
│  └─ AiInvocationInterceptor.java
├─ adapter/
│  ├─ Slf4jLogBridge.java
│  └─ OpenTelemetryBridge.java
└─ config/
```

------

### 6.4 日志插件（plugins）

#### 6.4.1 基础日志插件

```text
plugins/log-basic-plugin/
├─ writer/DatabaseLogWriter.java
├─ query/LogQueryProviderImpl.java
├─ api/LogController.java
└─ retention/DefaultRetentionPolicy.java
```

#### 6.4.2 AI 日志插件（推荐）

```text
plugins/ai-log-plugin/
├─ writer/AiTraceLogWriter.java
├─ analyzer/PromptAnalyzer.java
├─ analyzer/RagHitAnalyzer.java
└─ analyzer/ToolCallAnalyzer.java
```

------

## 7. AI 原生能力规划

### 7.1 AI 在系统中的位置

- AI 能力通过 SPI 定义（platform-core）
- AI SDK 适配在 infra
- AI 行为、策略、Agent 由插件实现

```text
spi/ai/
├─ ChatProvider.java
├─ RagProvider.java
├─ ToolExecutor.java
└─ AgentPolicy.java
```

------

### 7.2 AI 与日志的关系

- 每次 AI 调用必须产生 AI 日志
- 日志成为 AI 可解释性与记忆层基础
- AI 插件可以二次消费日志

------

## 8. 替换默认系统实现的方式（给开发者）

### 8.1 替换规则

| 想替换的能力 | 做法                        |
| ------------ | --------------------------- |
| 安全框架     | 提供新的 AuthProvider 插件  |
| 缓存         | 实现 CacheProvider SPI      |
| 持久化       | 实现 StorageProvider SPI    |
| AI 逻辑      | 实现 Chat / RAG / Agent SPI |
| 日志         | 实现 LogWriter 插件         |

------

### 8.2 禁止方式

- 禁止修改 platform-core
- 禁止在 infra 写业务逻辑
- 禁止插件直接访问数据库（除非其职责是存储插件）

------

## 9. 推荐开发顺序（重要）

1. platform-core：定义最小 SPI
2. platform-plugin：跑通插件加载
3. 一个 RBAC 插件
4. 一个基础日志插件
5. 一个 AI Chat 插件

------

## 10. 最终架构总结

> 这是一个：
>
> - 核心极小
> - 系统能力插件化
> - 日志与 AI 一等公民
> - 可长期演进的后台平台架构

本设计刻意避免过早复杂化，但**不会限制未来扩展到 IDE 级平台能力**。
