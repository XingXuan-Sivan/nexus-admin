# 插件生命周期设计

## 1. 文档目的

本文档用于说明项目插件系统的**完整生命周期模型**与**平台内部处理流程模型**，明确：

- 插件在系统中的**存在阶段**
- 插件生命周期与平台流程生命周期的**边界区分**
- 各阶段的**职责边界与责任主体**
- 插件对外生命周期的**最小完备集合**
- 平台内部流程的**工程化规范模型**

目标是保证插件系统：

- 语义清晰
- 边界稳定
- 模型可演进
- 架构可扩展
- 工程可维护

避免：

- 生命周期语义重叠
- 流程阶段混乱
- 插件感知平台内部机制
- 架构演进受限

------

## 2. 核心设计思想

### 2.1 双模型架构

插件系统采用**严格分层**的双模型结构：

```
┌─────────────────────────────────────────────────────────────┐
│                    平台层生命周期 (可演进)                      │
│  Discovery → Descriptor → Loader → Install → Start/Stop     │
│     ↓           ↓           ↓                               │
│  PluginSource → Parser → ClassLoader                        │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│                    插件层生命周期 (稳定协议)                    │
│         install → start → stop → uninstall                  │
│              (由插件自身实现 Plugin 接口)                      │
└─────────────────────────────────────────────────────────────┘
```

- **平台流程模型**：工程实现模型，可演进、可扩展、可替换
- **插件生命周期模型**：对外稳定协议，长期保持不变

### 2.2 职责分离原则

| 层级 | 职责 | 稳定性 |
|------|------|--------|
| Source | 插件发现，从不同来源扫描候选插件 | 可扩展 |
| Descriptor | 描述文件读取与解析 | 可扩展 |
| Loader | 类加载与实例化 | 可扩展 |
| Manager | 生命周期协调与状态管理 | 相对稳定 |
| Plugin | 业务逻辑与资源管理 | 稳定协议 |

### 2.3 资源边界建模

插件生命周期管理的本质是**资源管理边界建模**：

| 资源类型 | 示例 | 责任主体 | 生命周期阶段 |
|----------|------|----------|--------------|
| 物理资源 | 插件 JAR / 目录 / 配置文件 | 平台 | Discover → Install |
| JVM 资源 | ClassLoader / SPI 注册 | 平台 | Loader → Install |
| 业务资源 | 线程、连接、缓存、外部系统 | 插件 | start → stop |

## 3. 平台内部处理流程模型（工程模型）

### 3.1 流程总览

```
Discover（发现） → Resolve（解析/裁决） → Load（加载） → Install（安装执行）
```

### 3.2 Discover（发现阶段）

**语义**：
- 扫描各类来源（classpath / external / builtin / remote）
- 生成插件元数据集合
- 不进行安装、不产生副作用

**职责**：
- 路径扫描
- 资源识别
- 元信息读取

**设计要点**：
- 通过 `PluginSource` 接口抽象不同来源
- 支持本地目录、类路径、远程仓库等多种来源
- 来源可独立扩展，互不影响

### 3.3 Descriptor（描述阶段）

**语义**：
- 从插件路径读取描述文件
- 解析为元数据对象
- 支持多种描述文件格式

**职责**：
- 路径到描述文件的映射
- 描述文件格式解析
- 元数据验证

**设计要点**：
- `PluginDescriptorReader` 负责路径到描述的转换
- `PluginDescriptorParser` 专注格式解析
- 支持 JSON、YAML、XML 等多种格式扩展
- **路径解析策略**：通过 `PluginDescriptorPathResolver` 接口支持不同环境的描述文件定位
  - `PackedDirectoryResolver`：处理打包后的目录（如 `target/classes/META-INF/plugin.json`）
  - `DevDirectoryResolver`：处理开发环境源码目录（如 `src/main/resources/META-INF/plugin.json`）
  - `JarResolver`：处理 JAR 文件中的描述文件
  - `CompositePathResolver`：组合多个解析器，按优先级链式查找

### 3.4 Loader（加载阶段）

**语义**：
- 构建插件类加载器
- 实例化插件主类
- 准备运行环境

**职责**：
- ClassLoader 构建
- 插件主类加载
- 插件实例化

**设计要点**：
- 通过 `PluginLoader` 接口支持不同加载策略
- 类路径插件使用系统类加载器
- 外部插件使用独立 URLClassLoader

### 3.5 Resolve（解析裁决阶段）

**语义**：
- 插件 ID 去重
- 来源优先级裁决
- 冲突仲裁
- 生成最终安装计划

**职责**：
- pluginId 唯一性保证
- 来源优先级排序（EXTERNAL > BUILTIN > CLASSPATH）
- 决策最优插件来源

### 3.6 Install（安装执行阶段）

**语义**：
- 执行实际安装行为
- 调用插件 install 生命周期
- 注册平台管理结构

**职责**：
- 协调 Loader 完成加载
- 调用插件 install 回调
- 维护插件状态机
- 注册到插件管理器

> 以上流程属于**平台工程模型**，不对插件开发者暴露，不作为插件生命周期。

## 4. 插件对外生命周期模型（稳定协议）

### 4.1 生命周期阶段一览

```
install → start → stop → uninstall
```

这是一个**最小完备闭环生命周期模型**。

### 4.2 生命周期全流程示意

```
┌─────────┐
│ install │  插件被引入系统，初始化一次性资源
└────┬────┘
     ↓
┌─────────┐
│ start   │  插件开始运行，注册SPI、启动线程
└────┬────┘
     ↓
┌─────────┐
│ stop    │  插件停止运行，注销SPI、停止线程
└────┬────┘
     ↓
┌──────────┐
│ uninstall│  插件被永久移除，清理外部副作用
└──────────┘
```

### 4.3 各阶段详细说明

#### install（安装阶段）

**性质**：平台主导生命周期，插件可选择性参与

**语义**：插件被**正式引入系统环境**，但尚未进入运行态

**典型行为**：
- 初始化一次性资源（配置、缓存结构等）
- 验证运行环境
- 准备业务资源

**设计约束**：
- install ≠ start
- install 阶段禁止启动业务线程
- install 阶段禁止对外提供服务
- install 失败 → 插件不可用

#### start（启动阶段）

**性质**：插件主导生命周期，插件行为入口

**语义**：插件正式进入**运行态**

**典型行为**：
- 注册 SPI 实现
- 启动后台线程
- 启动调度任务
- 对外提供功能能力

**设计约束**：
- start 应具备幂等语义
- start 失败 → 插件进入 FAILED 状态

#### stop（停止阶段）

**性质**：插件主导生命周期，start 的对称操作

**语义**：插件停止运行，但仍保留在系统中

**典型行为**：
- 注销 SPI 实现
- 停止线程
- 停止任务调度
- 释放运行期资源

**设计说明**：
- stop 不删除插件文件
- stop 后插件可再次 start

#### uninstall（卸载阶段）

**性质**：终结生命周期，插件永久移除

**语义**：插件被**彻底移出系统生态**

**典型行为**：
- 清理外部系统状态
- 删除磁盘缓存
- 清理临时文件
- 解除外部依赖关系

**平台侧强制行为**：
- 若处于运行态：自动执行 stop
- 关闭插件 ClassLoader
- 清理 JVM 资源
- 删除插件物理文件
- 从插件注册表移除

## 5. 架构扩展性设计

### 5.1 可扩展点

| 扩展点 | 接口 | 说明 |
|--------|------|------|
| 插件来源 | `PluginSource` | 支持本地目录、远程仓库、数据库等 |
| 描述读取 | `PluginDescriptorReader` | 支持不同格式描述文件 |
| 描述解析 | `PluginDescriptorParser` | 支持 JSON、YAML、XML 等 |
| 路径解析 | `PluginDescriptorPathResolver` | 支持不同环境的描述文件路径定位策略 |
| 类加载 | `PluginLoader` | 支持不同加载策略 |
| 事件监听 | `PluginLifecycleListener` | 自定义生命周期处理逻辑 |

### 5.2 扩展示例

**新增远程插件源**：
```
实现 RemoteRepositorySource implements PluginSource
```

**新增 YAML 描述文件支持**：
```
实现 YamlDescriptorReader implements PluginDescriptorReader
```

**新增自定义路径解析策略**（如支持 Gradle 项目结构）：
```
实现 CustomPathResolver implements PluginDescriptorPathResolver
```

**自定义生命周期监听**：
```
实现 PluginLifecycleListener，用于监控、审计、告警等
```

------

## 6. 生命周期事件机制

### 6.1 事件类型

平台通过事件机制将生命周期各阶段暴露给监听者：

| 阶段 | 事件 |
|------|------|
| Discover | DISCOVER_START, DISCOVER_END, DISCOVERED |
| Resolve | RESOLVE_START, RESOLVE_END, RESOLVED |
| Install | INSTALL_START, INSTALL_END, INSTALLED, SKIPPED, FAILED |
| Start | STARTING, STARTED |
| Stop | STOPPING, STOPPED |
| Uninstall | UNINSTALLING, UNINSTALLED |

### 6.2 事件用途

- **日志记录**：`LoggingLifecycleListener` 记录各阶段日志
- **监控告警**：监听失败事件触发告警
- **审计追踪**：记录插件全生命周期轨迹
- **扩展处理**：在特定阶段执行自定义逻辑

## 7. 插件状态模型

```
enum PluginState {
    INSTALLED,   // 已安装，可启动
    STARTED,     // 运行中
    STOPPED,     // 已停止，可重新启动
    UNINSTALLED, // 已卸载
    FAILED       // 失败状态
}
```

### 状态转换约束

```
INSTALLED → STARTED → STOPPED → UNINSTALLED
        ↘
         FAILED
```

## 8. 平台侧职责模型总结

| 阶段 | 平台职责 | 对应组件 | 所在模块 |
|------|----------|----------|----------|
| Discover | 扫描、识别、候选生成 | PluginSource | core |
| Descriptor | 描述文件读取、解析 | PluginDescriptorReader/Parser | core |
| Loader | ClassLoader 构建、插件实例化 | PluginLoader | core |
| Resolve | 去重、裁决、冲突处理 | PluginManager | core |
| Install | 加载、install 回调调用 | PluginManager | core |
| start | 调用插件 start | PluginManager | core |
| stop | 调用插件 stop | PluginManager | core |
| uninstall | stop → uninstall → 清理 → 删除文件 | PluginManager | core |

------

## 9. 生命周期与插件升级

插件升级模型：

```
uninstall(oldPlugin)
install(newPlugin)
start(newPlugin)
```

无需引入额外生命周期即可支持：

- 热升级
- 回滚
- 版本切换

------

## 10. 总结

### 核心原则

1. **模型分层清晰**：平台流程与插件生命周期严格分离
2. **边界稳定**：插件生命周期作为长期稳定协议
3. **流程可演进**：平台内部实现可重构、可替换
4. **协议简单**：最小完备的生命周期集合

### 架构优势

- **可扩展性**：通过接口支持多种来源、格式、加载策略
- **可测试性**：各组件职责单一，便于单元测试
- **可维护性**：清晰的职责边界，降低代码耦合
- **可观测性**：事件机制支持全生命周期监控

> 一个成熟的插件系统，不是生命周期多，而是：
>
> **模型分层清晰、边界稳定、协议简单、流程可演进。**
