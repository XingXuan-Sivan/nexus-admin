# 整体架构设计

------

# 1. 项目简介

**Nexus Admin** 是一个面向后台管理场景的 **完全微内核（Microkernel）架构插件化业务扩展平台后端**。

系统采用严格微内核模型构建：

- 内核是唯一稳定运行时
- 所有系统能力均以插件形式提供
- 技术框架不进入核心
- 业务能力不内置于平台

平台目标：

- **极小核心**：核心保持稳定、长期演进
- **能力外置**：所有可变能力插件化
- **强隔离**：插件之间无直接耦合
- **可替换性**：任何能力可被新插件替代

------

# 2. 总体架构概览

## 2.1 模块总览

```text
backend/
├─ nexus-admin-core/        # 微内核运行时与插件物理加载实现
├─ nexus-admin-api/         # 系统能力 SPI 定义与插件开发 API
├─ nexus-admin-app/         # 启动与系统装配层
└─ plugins/                 # 插件实现集合
```

------

## 2.2 架构核心原则

1. Core 是系统唯一不可插件化模块
2. 所有系统能力必须通过 SPI 抽象
3. 插件是唯一能力实现形式
4. 插件之间不得直接依赖
5. 技术框架不得进入核心
6. 核心负责能力调度，插件负责能力实现

------

# 3. 模块职责说明

------

# 3.1 nexus-admin-core

## 3.1.1 核心定位

> 微内核模块。是系统运行时内核、能力调度中心与插件物理加载实现层。

该模块承担：

- 插件生命周期管理
- 插件依赖解析
- 插件状态管理
- 扩展注册中心运行时实现
- 运行时事件总线
- 插件调度能力
- 能力选择与替换机制
- 插件目录扫描
- 插件 jar 加载
- 描述文件解析
- 类加载器隔离
- 实例化插件主类

它是整个系统的唯一稳定运行时。

------

## 3.1.2 语义边界

nexus-admin-core：

- 不包含任何技术框架
- 不依赖 Spring / Web / ORM / AI SDK
- 不包含具体能力实现
- 不定义具体业务 SPI 接口

它只负责：

插件运行时管理、能力调度机制与物理加载实现。

------

------

## 3.1.4 核心能力模型说明

### Plugin

插件抽象定义：

- 插件唯一标识
- 插件生命周期方法
- 插件初始化入口
- 插件关闭回调

------

### PluginState

插件状态枚举（示例）：

- INSTALLED
- RESOLVED
- STARTED
- STOPPED
- FAILED

------

### PluginLifecycle

定义生命周期阶段（示例）：

- load
- resolve
- start
- stop
- unload

------

### PluginManager

核心运行时调度器：

- 管理插件注册
- 管理生命周期
- 调用依赖解析器
- 控制插件启停
- 与 Registry 交互

------

### Registry

统一能力注册中心运行时实现：

- SPI 实现注册
- SPI 查询
- 优先级管理
- 能力替换支持

------

### DependencyResolver

- 插件依赖解析
- 有向图构建
- 拓扑排序
- 循环依赖检测

------

### EventBus

- 插件间事件通信
- 解耦消息传递
- 支持同步/异步

------

# 3.2 nexus-admin-api

## 3.2.1 核心定位

> 系统能力契约与插件开发接口模块。专门用于定义平台能力接口（SPI）和面向插件开发者的编程 API。

该模块包含两部分：

- **SPI 层**：定义各类系统能力接口（如存储、认证、AI 等）
- **Infra 层**：提供插件开发所需的基础接口、注解、上下文 API 和扩展声明机制

不包含：

- 实现代码
- 运行时逻辑
- 生命周期管理
- 注册中心实现

它是能力的“契约层”与插件的“开发工具箱”。

------

## 3.2.2 语义边界

nexus-admin-api：

- 不依赖 core
- 不依赖 app
- 不包含技术实现
- 不参与运行时调度

它仅定义：

- 平台拥有哪些能力接口
- 插件如何声明和使用这些能力

------

------

## 3.2.4 设计原则

- SPI 仅定义接口
- 不允许包含默认实现
- 不允许依赖第三方框架
- 语义必须稳定
- 版本向后兼容
- 插件开发 API 必须简洁、安全、易用

------

# 3.3 plugins

## 核心定位

> 能力实现模块。是包含所有系统能力的实现集合。

插件：

- 依赖 nexus-admin-api 的能力接口与开发 API
- 不得依赖 nexus-admin-core（仅通过接口交互）
- 不得修改核心

------

## 插件标准结构

### 插件 jar 结构

```text
storage-plugin.jar
│
├── META-INF/plugin.json
└── com.example.storage
      └── S3StoragePlugin.class
```

------

### plugin.json 示例

```json
{
  "id": "s3-storage",
  "version": "1.0.0",
  "mainClass": "com.example.storage.S3StoragePlugin",
  "dependencies": []
}
```

字段说明：

| 字段         | 说明         |
| ------------ | ------------ |
| id           | 插件唯一标识 |
| version      | 插件版本     |
| mainClass    | 插件主类     |
| dependencies | 依赖插件 ID  |

------

# 3.4 nexus-admin-app

启动层。职责：

- 创建核心运行环境
- 初始化 PluginManager
- 初始化 Registry
- 指定插件目录
- 启动插件加载流程

不包含任何业务能力。

------

# 4. 模块依赖关系

## 4.1 依赖方向图

```text
nexus-admin-app
    ↓
nexus-admin-core
    ↓
nexus-admin-api
    ↑
plugins
```

------

## 4.2 严格约束

禁止：

- 插件之间直接依赖
- 插件依赖 nexus-admin-core（仅允许依赖 nexus-admin-api）
- core 依赖技术框架
- API 模块包含实现
- SPI 定义依赖运行时实现

------

# 5. 系统能力模型

所有能力通过 nexus-admin-api 中的 SPI 定义。

定义了一个后台管理系统所需的基本能力，包括：

- 认证能力
- 权限能力
- 存储能力
- 缓存能力
- 日志能力
- AI 能力
- 路由能力
- 事件能力

核心只负责调度，不提供实现。

------

# 6. 成熟微内核可扩展能力

| 能力           | 说明                         |
| -------------- | ---------------------------- |
| 热加载         | 支持运行时加载/卸载插件      |

| 版本冲突隔离   | 多版本插件并存               |
| 依赖拓扑排序   | 有向图解析与顺序加载         |
| 能力优先级仲裁 | 多实现选择策略               |
| 插件健康检查   | 运行时状态监控               |
| 插件资源隔离   | ClassLoader 级隔离           |
| 分布式插件同步 | 集群环境能力同步             |

------

# 7. 架构演进能力

该架构天然支持：

- 能力替换
- 能力扩展
- 插件新增
- 插件删除
- 技术栈迁移
- AI 能力持续演进
- 企业能力沉淀
- 插件商业化

无需修改核心。

------

# 8. 如果持续进化，它会变成什么？

如果该系统持续演进，它将成为：

### 1. 平台型产品

一个可承载多能力、多团队协作的运行时平台。

------

### 2. 插件市场型系统

支持：

- 插件发布
- 插件版本管理
- 插件在线安装
- 插件付费分发

------

### 3. 企业内部能力容器

企业可以：

- 将认证、存储、日志、AI 等能力模块化
- 独立升级
- 独立替换
- 形成内部能力资产库

------

# 9. 最终架构本质

它本质上是：

> 一个 Java 运行时微内核平台。

而不是传统后端系统。

它是：

- 插件运行时
- 能力调度中心
- 企业能力容器
- 可演进架构核心

核心保持稳定，能力持续进化。

这是一种长期主义架构模型。
