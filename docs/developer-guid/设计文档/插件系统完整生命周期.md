# 插件系统完整生命周期说明

## 1. 文档目的

本文档用于说明项目插件系统的**完整生命周期模型**与**平台内部处理流程模型**，明确：

- 插件在系统中的**存在阶段**
- 插件生命周期与平台流程生命周期的**边界区分**
- 各阶段的**职责边界与责任主体**
- 插件对外生命周期的**最小完备集合**
- 平台内部流程的**工程化规范模型**

目标是保证插件系统：

- 语义清晰
- 边界稳定
- 模型可演进
- 架构可扩展
- 工程可维护

避免：

- 生命周期语义重叠
- 流程阶段混乱
- 插件感知平台内部机制
- 架构演进受限

------

## 2. 生命周期设计原则

### 2.1 对外生命周期最小化原则

生命周期一旦对插件开发者暴露，即成为**长期稳定协议（Stable Contract）**，几乎不可删除。

因此遵循原则：

- **只暴露插件行为语义相关阶段**
- **不暴露平台内部流程阶段**
- **不将工程流程包装成生命周期**
- **生命周期必须具备不可合并的独立语义**

------

### 2.2 插件系统资源模型

插件生命周期管理的本质是**资源管理边界建模**，涉及三类资源：

| 资源类型 | 示例                       | 责任主体 |
| -------- | -------------------------- | -------- |
| 物理资源 | 插件 JAR / 目录 / 配置文件 | 平台     |
| JVM 资源 | ClassLoader / SPI 注册     | 平台     |
| 业务资源 | 线程、连接、缓存、外部系统 | 插件     |

生命周期阶段是否存在，取决于是否存在**不可合并的资源边界**。

------

## 3. 生命周期与平台流程模型区分

### 3.1 模型分层原则

插件系统采用**双模型结构**：

```text
平台流程模型（Platform Pipeline）  → 内部工程流程
插件生命周期模型（Plugin Lifecycle）→ 对外稳定协议
```

两者严格隔离：

- 平台流程模型：**工程实现模型**，可演进
- 插件生命周期模型：**协议模型**，长期稳定

------

## 4. 平台内部插件处理流程模型（工程模型）

```text
Discover（发现） → Resolve（解析/裁决） → Install（安装执行）
```

### 4.1 Discover（发现阶段）

语义：

- 扫描各类来源（classpath / external / builtin / remote）
- 生成插件候选集合
- 不进行安装、不产生副作用

职责：

- 路径扫描
- 资源识别
- 元信息读取

### 4.2 Resolve（解析裁决阶段）

语义：

- 插件 ID 去重
- 来源优先级裁决
- 冲突仲裁
- 生成最终安装计划

职责：

- pluginId 唯一性保证
- 来源优先级排序
- 决策最优插件来源

### 4.3 Install（安装执行阶段）

语义：

- 执行实际安装行为
- 调用插件 install 生命周期
- 注册平台管理结构

职责：

- ClassLoader 构建
- 插件实例化
- PluginContext 构建
- 插件注册

> 该流程属于**平台工程模型**，不对插件开发者暴露，不作为插件生命周期。

------

## 5. 插件对外生命周期模型（稳定协议）

### 5.1 生命周期阶段一览

```text
install → start → stop → uninstall
```

这是一个**最小完备闭环生命周期模型**。

------

### 5.2 生命周期全流程示意

```text
┌─────────┐
│ install │  插件被引入系统
└────┬────┘
     ↓
┌─────────┐
│ start   │  插件开始运行
└────┬────┘
     ↓
┌─────────┐
│ stop    │  插件停止运行
└────┬────┘
     ↓
┌──────────┐
│ uninstall│  插件被永久移除
└──────────┘
```

------

## 6. 各生命周期阶段详细说明

------

## 6.1 install（安装阶段）

### 生命周期性质

- **平台主导生命周期**
- 插件可选择性参与

### 语义说明

install 表示插件被**正式引入系统环境**，但尚未进入运行态。

典型行为包括：

- 插件物理资源准备
- 元信息校验（plugin.yml / descriptor）
- ClassLoader 创建
- 插件主类实例化
- PluginContext 构建

### 插件侧接口（可选）

```java
default void install(PluginContext context) {
    // 初始化一次性资源（可选）
}
```

### 设计约束

- install ≠ start
- install 阶段禁止启动业务线程
- install 阶段禁止对外提供服务
- install 失败 → 插件不可用

------

## 6.2 start（启动阶段）

### 生命周期性质

- **插件主导生命周期**
- 插件行为入口

### 语义说明

start 表示插件正式进入**运行态**。

典型行为包括：

- 注册 SPI 实现
- 启动后台线程
- 启动调度任务
- 对外提供功能能力

### 插件接口

```java
void start(PluginContext context);
```

### 约束

- start 应具备幂等语义或可控重入
- start 失败 → 插件进入 FAILED 状态

------

## 6.3 stop（停止阶段）

### 生命周期性质

- **插件主导生命周期**
- start 的对称操作

### 语义说明

stop 表示插件停止运行，但仍保留在系统中。

典型行为包括：

- 注销 SPI 实现
- 停止线程
- 停止任务调度
- 释放运行期资源

### 插件接口

```java
void stop(PluginContext context);
```

### 设计说明

- stop 不删除插件文件
- stop 后插件可再次 start

------

## 6.4 uninstall（卸载阶段）

### 生命周期性质

- **终结生命周期**
- 插件永久移除

### 语义说明

uninstall 表示插件被**彻底移出系统生态**。

典型行为包括：

- 清理外部系统状态
- 删除磁盘缓存
- 清理临时文件
- 解除外部依赖关系

### 插件接口（可选）

```java
default void uninstall(PluginContext context) {
    // 清理外部副作用
}
```

### 平台侧强制行为

- 若处于运行态：自动执行 stop
- 关闭插件 ClassLoader
- 清理 JVM 资源
- 删除插件物理文件
- 从插件注册表移除

------

## 7. 非生命周期阶段说明（平台内部阶段）

以下阶段属于**平台工程流程**，不作为插件生命周期暴露：

| 阶段     | 归属模型 | 说明                   |
| -------- | -------- | ---------------------- |
| discover | 平台流程 | 插件扫描与发现         |
| resolve  | 平台流程 | 去重、裁决、仲裁       |
| load     | 平台流程 | 安装过程的一部分       |
| unload   | 平台流程 | uninstall 内部实现细节 |

原则：

> 插件只感知“行为生命周期”，不感知“平台流程生命周期”。

------

## 8. 插件生命周期接口定义（最终推荐）

```java
public interface Plugin {

    default void install(PluginContext context) {
    }

    void start(PluginContext context);

    void stop(PluginContext context);

    default void uninstall(PluginContext context) {
    }
}
```

------

## 9. 插件状态模型（推荐）

```java
enum PluginState {
    INSTALLED,
    STARTED,
    STOPPED,
    UNINSTALLED,
    FAILED
}
```

### 状态转换约束

```text
INSTALLED → STARTED → STOPPED → UNINSTALLED
        ↘
         FAILED
```

------

## 10. 平台侧职责模型总结

| 阶段      | 平台职责                           |
| --------- | ---------------------------------- |
| Discover  | 扫描、识别、候选生成               |
| Resolve   | 去重、裁决、冲突处理               |
| Install   | 构建环境、加载、注册、install 调用 |
| start     | 调用插件 start                     |
| stop      | 调用插件 stop                      |
| uninstall | stop → uninstall → 清理 → 删除文件 |

------

## 11. 生命周期与插件升级关系

插件升级模型：

```text
uninstall(oldPlugin)
install(newPlugin)
start(newPlugin)
```

无需引入额外生命周期即可支持：

- 热升级
- 回滚
- 版本切换

------

## 12. 总结

- 插件系统采用**双模型结构**：
  - 平台流程模型（工程模型）
  - 插件生命周期模型（协议模型）
- 插件对外生命周期应当：
  - 少
  - 稳定
  - 语义独立
  - 不可合并
- 平台流程模型应当：
  - 可演进
  - 可扩展
  - 可重构
  - 可替换

> 一个成熟的插件系统，不是生命周期多，而是：
>
> **模型分层清晰、边界稳定、协议简单、流程可演进。**
