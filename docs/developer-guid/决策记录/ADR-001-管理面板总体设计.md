# **管理面板总体设计**

---

# 一、设计背景

在微内核架构中，系统核心（Kernel）仅负责：

- 插件生命周期管理（PluginManager）
- 配置管理（ConfigManager）
- 运行时上下文（PluginContext）

但缺乏一个统一的**对外控制与观测入口**。

因此需要构建一个：

```text
管理面板系统（Admin Plane / Control Plane）
```

用于：

- 对系统进行操作（控制）
- 对系统进行观察（观测）
- 对系统进行配置（管理）

---

# 二、设计目标

本系统的设计目标如下：

```text
1. 提供统一的 RESTful 管理接口（供前端调用）
2. 完全复用现有 app 模块（Spring Boot 宿主）
3. 不侵入核心（与核心解耦）
4. 作为系统插件存在（可插拔）
5. 支持后续能力扩展（插件化扩展管理面板能力）
```

---

# 三、设计原则

## 3.1 控制平面 / 数据平面分离

参考：

- Kubernetes
- Apache Kafka

```text
Control Plane（管理面板） ≠ Data Plane（业务逻辑）
```

管理面板只负责：

- 管理
- 调度
- 查询

不承载业务数据处理。

---

## 3.2 单一宿主容器原则

```text
系统仅存在一个 Spring Boot 容器（app 模块）
```

管理面板：

- 不启动新服务
- 不创建独立运行时
- 作为插件接入宿主容器

---

## 3.3 插件化扩展原则

参考：

- Grafana（插件扩展面板）
- Kibana（模块化 UI）

```text
管理面板本身也是“插件能力的聚合入口”
```

---

## 3.4 解耦原则

```text
Controller → Application → 解耦层 → Core
```

禁止：

```text
Controller → PluginManager（直连）
```

---

# 四、总体架构

## 4.1 分层结构

```text
┌──────────────────────────────┐
│        Frontend UI           │
└──────────────┬───────────────┘
               │ REST API
┌──────────────▼───────────────┐
│      Admin Plugin（控制层）   │
│  - Controller                │
│  - Service                   │
│  - DTO / View                │
└──────────────┬───────────────┘
               │ 解耦层
┌──────────────▼───────────────┐
│          Core Layer          │
│  - PluginManager             │
│  - ConfigManager             │
│  - Core Facades              │
└──────────────────────────────┘
```

---

## 4.2 运行时结构

```text
Spring Boot（app）
│
├─ Core Beans
│
├─ Plugin Integration Layer
│   └─ PluginSpringManager
│
└─ Plugin Context（每插件一个子容器）
    ├─ admin-plugin（管理面板）
    └─ other plugins
```

# 七、单账号机制设计（重点）

## 7.1 设计目标

在以下条件下仍可使用系统：

```text
- 无数据库
- 无用户系统
- 无权限模块
```

---

## 7.2 设计模型

```text
Bootstrap Identity（引导身份）
```

即：

> 系统提供一个默认管理员账号，用于最低限度的访问控制

---

## 7.3 实现策略（设计层面）

### 方式：配置驱动的内存身份

```text
用户来源：配置文件（Config）
存储方式：内存
认证方式：简单认证（Basic / Token）
```

---

## 7.4 生命周期

```text
系统启动
 → 读取配置
   → 构建默认用户
     → 注入认证模块
```

---

## 7.5 安全策略

```text
- 默认账号仅用于开发 / 内网
- 允许通过配置关闭
- 支持后续替换为完整用户系统
```

---

## 7.6 设计原则

```text
1. 不依赖外部系统
2. 不引入复杂度
3. 可平滑升级为完整权限体系
```

---

# 十一、总结（设计本质）

该系统的本质是：

```text
一个基于插件系统构建的“控制平面”
```

其核心特征：

```text
- 轻量（最小可用）
- 解耦
- 可扩展（插件化）
- 可演进（从单账号 → RBAC）
```

---

# 十二、关键结论（最重要）

> ❗ 管理面板不是“功能集合”，而是“系统控制能力的统一出口”

以及：

> ❗ 默认单账号不是“简化版用户系统”，而是“Bootstrap 能力”
