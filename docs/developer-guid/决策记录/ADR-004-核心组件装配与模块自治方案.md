# ADR-004: 核心组件装配与模块自治方案

------

## 背景与问题

### 1. 已有决策回顾

ADR-003（议题六"装配职责重新划分"）决定在 api 模块新增 `CoreAutoConfig`，负责装配 core 模块的六个默认实现：

| Bean | 默认实现 | 来源包 |
|------|---------|--------|
| EventBus | SyncEventBus | `core.event` |
| ExtensionRegistry | DefaultExtensionRegistry | `core.extension` |
| PluginRegistry | DefaultPluginRegistry | `core.plugin` |
| VersionManager | DefaultVersionManager | `core.plugin.resolve.version` |
| DependenceManager | DefaultDependenceManager | `core.plugin.resolve` |
| PluginLoader | DefaultPluginLoader | `core.plugin.loader` |

ADR-003 的装配方式：在 api 模块中用 `@Bean` + `@ConditionalOnMissingBean` 逐个声明。

### 2. ADR-003 决策的不足

重新审视后，该决策存在两个问题：

**问题一：架构归属错位**

六个 Bean 的类型 100% 来自 core 模块，装配代码却在 api 模块。这违反了"谁定义、谁配置"的内聚原则。api 模块不应替 core 决定其默认实现。

**问题二：core 模块无法独立使用**

如果一个外部项目仅引入 `nexus-admin-core`（不引入 api，不需要管理面板和 Web 能力），它将无法得到任何自动装配——必须手动编写所有 Bean 的创建代码。core 作为"微内核运行时"的独立复用价值被削弱。

**问题三：装配方式耦合了 Spring**

当前的 `@Bean` + `@ConditionalOnMissingBean` 方式与 Spring 框架强耦合。core 模块的设计原则之一是"技术框架不得进入核心"（整体架构 §3.1.2），但默认装配能力同样不应与 Spring 绑定。

### 3. 根本原因

六个默认实现的依赖关系是一个有向无环图：

```
EventBus:         无依赖
PluginRegistry:   无依赖
VersionManager:   无依赖
PluginLoader:     无依赖
ExtensionRegistry: → EventBus
DependenceManager: → VersionManager
```

这个简单、稳定的依赖图完全可以用纯 Java 代码表达，不需要 DI 容器。

------

## 决策方案

采用 **Builder 模式（CoreRuntime）** 在 core 模块完成装配，在 api 模块保留 **薄 Spring 桥接层**。

### 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                     nexus-admin-core                     │
│  (零框架依赖：slf4j、minimal-json、snakeyaml 仅此而已)    │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │              CoreRuntime (Builder)               │    │
│  │                                                 │    │
│  │  CoreRuntime.defaults()  → 全默认装配            │    │
│  │  CoreRuntime.builder()   → 选择性覆盖            │    │
│  │      .eventBus(new AsyncEventBus())              │    │
│  │      .versionManager(new MyVersionManager())     │    │
│  │      .build()                                   │    │
│  │                                                 │    │
│  │  访问器: .eventBus() .extensionRegistry() ...    │    │
│  └─────────────────────────────────────────────────┘    │
└──────────────────────┬──────────────────────────────────┘
                       │ 依赖
┌──────────────────────▼──────────────────────────────────┐
│                    nexus-admin-api                       │
│  (引入 Spring Web，提供 REST 与管理面板)                  │
│                                                         │
│  ┌─────────────────────────────────────────────────┐    │
│  │       CoreRuntimeSpringBridge (@Configuration)   │    │
│  │                                                 │    │
│  │  @Bean @ConditionalOnMissingBean                 │    │
│  │  CoreRuntime → coreRuntime()                    │    │
│  │  EventBus → coreRuntime().eventBus()            │    │
│  │  ExtensionRegistry → coreRuntime().extension... │    │
│  │  ... 所有 Bean 通过访问器委托给 CoreRuntime       │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### CoreRuntime 设计（core 模块）

```java
// 路径: nexus-admin-core/src/main/java/com/nexusadmin/core/CoreRuntime.java
package com.nexusadmin.core;

import com.nexusadmin.core.event.EventBus;
import com.nexusadmin.core.event.SyncEventBus;
import com.nexusadmin.core.extension.DefaultExtensionRegistry;
import com.nexusadmin.core.extension.ExtensionRegistry;
import com.nexusadmin.core.plugin.DefaultPluginRegistry;
import com.nexusadmin.core.plugin.PluginRegistry;
import com.nexusadmin.core.plugin.loader.impl.DefaultPluginLoader;
import com.nexusadmin.core.plugin.loader.PluginLoader;
import com.nexusadmin.core.plugin.resolve.impl.DefaultDependenceManager;
import com.nexusadmin.core.plugin.resolve.DependenceManager;
import com.nexusadmin.core.plugin.resolve.VersionManager;
import com.nexusadmin.core.plugin.resolve.impl.DefaultVersionManager;

import java.util.Objects;

/**
 * Core 运行时聚合根，负责装配核心组件的默认实例。
 * <p>
 * 所有组件均可通过 Builder 选择性覆盖，未指定的使用默认实现。
 * 依赖关系在 {@link Builder#build()} 中自动注入，无需外部 DI 容器。
 * <p>
 * <strong>使用示例：</strong>
 * <pre>{@code
 * // 1. 全默认（最小启动）
 * CoreRuntime rt = CoreRuntime.defaults();
 *
 * // 2. 选择性覆盖（如替换事件总线实现）
 * CoreRuntime rt = CoreRuntime.builder()
 *     .eventBus(new MyAsyncEventBus())
 *     .build();
 *
 * // 3. 访问组件
 * EventBus bus = rt.eventBus();
 * ExtensionRegistry registry = rt.extensionRegistry();
 * }</pre>
 *
 * @since 0.2.0
 */
public final class CoreRuntime {

    private final EventBus eventBus;
    private final ExtensionRegistry extensionRegistry;
    private final PluginRegistry pluginRegistry;
    private final VersionManager versionManager;
    private final DependenceManager dependenceManager;
    private final PluginLoader pluginLoader;

    private CoreRuntime(Builder builder) {
        this.eventBus = Objects.requireNonNull(builder.eventBus, "eventBus");
        this.pluginRegistry = Objects.requireNonNull(builder.pluginRegistry, "pluginRegistry");
        this.versionManager = Objects.requireNonNull(builder.versionManager, "versionManager");
        this.pluginLoader = Objects.requireNonNull(builder.pluginLoader, "pluginLoader");

        // 依赖注入：在构造函数中完成，利用 Builder 提供的可选覆盖
        this.extensionRegistry = builder.extensionRegistry != null
                ? builder.extensionRegistry
                : new DefaultExtensionRegistry(this.eventBus);

        this.dependenceManager = builder.dependenceManager != null
                ? builder.dependenceManager
                : new DefaultDependenceManager(this.versionManager);
    }

    // ==================== 组件访问器 ====================

    public EventBus eventBus() {
        return eventBus;
    }

    public ExtensionRegistry extensionRegistry() {
        return extensionRegistry;
    }

    public PluginRegistry pluginRegistry() {
        return pluginRegistry;
    }

    public VersionManager versionManager() {
        return versionManager;
    }

    public DependenceManager dependenceManager() {
        return dependenceManager;
    }

    public PluginLoader pluginLoader() {
        return pluginLoader;
    }

    // ==================== 快速创建 ====================

    /**
     * 使用全部默认实现创建 CoreRuntime。
     *
     * @return 配置完成的 CoreRuntime 实例
     */
    public static CoreRuntime defaults() {
        return builder().build();
    }

    /**
     * 创建 Builder 实例。
     *
     * @return Builder
     */
    public static Builder builder() {
        return new Builder();
    }

    // ==================== Builder ====================

    public static class Builder {
        private EventBus eventBus;
        private ExtensionRegistry extensionRegistry;
        private PluginRegistry pluginRegistry;
        private VersionManager versionManager;
        private DependenceManager dependenceManager;
        private PluginLoader pluginLoader;

        public Builder eventBus(EventBus val)             { this.eventBus = val; return this; }
        public Builder extensionRegistry(ExtensionRegistry val) { this.extensionRegistry = val; return this; }
        public Builder pluginRegistry(PluginRegistry val) { this.pluginRegistry = val; return this; }
        public Builder versionManager(VersionManager val) { this.versionManager = val; return this; }
        public Builder dependenceManager(DependenceManager val) { this.dependenceManager = val; return this; }
        public Builder pluginLoader(PluginLoader val)     { this.pluginLoader = val; return this; }

        /**
         * 构建 CoreRuntime，未指定组件使用默认实现。
         *
         * @return CoreRuntime 实例
         */
        public CoreRuntime build() {
            if (this.eventBus == null)       this.eventBus = new SyncEventBus();
            if (this.pluginRegistry == null) this.pluginRegistry = new DefaultPluginRegistry();
            if (this.versionManager == null) this.versionManager = new DefaultVersionManager();
            if (this.pluginLoader == null)   this.pluginLoader = new DefaultPluginLoader();
            return new CoreRuntime(this);
        }
    }
}
```

**设计要点**：

1. **不可变**：`CoreRuntime` 实例创建后不可修改，线程安全
2. **依赖注入在构造时完成**：`ExtensionRegistry` 和 `DependenceManager` 的依赖在 Builder 中自动注入，而非事后 setter
3. **Builder 在 `build()` 中补全默认值**：调用者未提供 → 使用默认实现 → 传入构造器完成注入
4. **零外部依赖**：仅依赖 `java.util.Objects`，不引入任何框架

### Spring 桥接层设计（api 模块）

```java
// 路径: nexus-admin-api/src/main/java/com/nexusadmin/api/config/CoreAutoConfig.java
// （复用现有文件名，但内容完全替换）
package com.nexusadmin.api.config;

import com.nexusadmin.core.runtime.CoreRuntime;
import com.nexusadmin.core.event.EventBus;
import com.nexusadmin.core.extension.ExtensionRegistry;
import com.nexusadmin.core.plugin.PluginRegistry;
import com.nexusadmin.core.plugin.loader.PluginLoader;
import com.nexusadmin.core.plugin.resolve.DependenceManager;
import com.nexusadmin.core.plugin.resolve.VersionManager;
import org.springframework.boot.autoconfigure.condition.ConditionalOnMissingBean;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * Core 模块 Spring 桥接配置。
 * <p>
 * 将 CoreRuntime 装配的组件桥接到 Spring 容器，所有 Bean 均带
 * {@link ConditionalOnMissingBean} 保护，允许上层覆盖。
 * <p>
 * 桥接层不参与组件创建逻辑——创建与依赖注入由 CoreRuntime 全权负责。
 */
@Configuration
public class CoreAutoConfig {

    /**
     * Core 运行时聚合根。
     */
    @Bean
    @ConditionalOnMissingBean
    public CoreRuntime coreRuntime() {
        return CoreRuntime.defaults();
    }

    @Bean
    @ConditionalOnMissingBean
    public EventBus eventBus(CoreRuntime rt) {
        return rt.eventBus();
    }

    @Bean
    @ConditionalOnMissingBean
    public ExtensionRegistry extensionRegistry(CoreRuntime rt) {
        return rt.extensionRegistry();
    }

    @Bean
    @ConditionalOnMissingBean
    public PluginRegistry pluginRegistry(CoreRuntime rt) {
        return rt.pluginRegistry();
    }

    @Bean
    @ConditionalOnMissingBean
    public VersionManager versionManager(CoreRuntime rt) {
        return rt.versionManager();
    }

    @Bean
    @ConditionalOnMissingBean
    public DependenceManager dependenceManager(CoreRuntime rt) {
        return rt.dependenceManager();
    }

    @Bean
    @ConditionalOnMissingBean
    public PluginLoader pluginLoader(CoreRuntime rt) {
        return rt.pluginLoader();
    }
}
```

**桥接层职责边界**：
- ✅ 将 `CoreRuntime` 暴露为 Spring Bean
- ✅ 将各组件通过访问器委托暴露为独立 Bean（保持向后兼容）
- ✅ 声明 `@ConditionalOnMissingBean` 保留覆盖能力
- ❌ 不包含任何组件创建逻辑
- ❌ 不包含依赖注入逻辑

### 覆盖机制

```
优先级：app @Bean > api @ConditionalOnMissingBean > CoreRuntime 默认值
```

**场景 1：覆盖单个组件（Spring 环境）**

```java
// 在 app 模块中声明同类型 Bean 即可覆盖
@Bean
public EventBus eventBus() {
    return new AsyncEventBus();  // 替换默认的 SyncEventBus
}
```

**场景 2：覆盖整个 CoreRuntime（Spring 环境）**

```java
// 声明 CoreRuntime Bean 即可级联替换所有子组件
@Bean
public CoreRuntime coreRuntime() {
    return CoreRuntime.builder()
            .eventBus(new AsyncEventBus())
            .pluginLoader(new CustomPluginLoader())
            .build();
}
```

**场景 3：非 Spring 环境直接使用**

```java
CoreRuntime rt = CoreRuntime.defaults();
EventBus bus = rt.eventBus();
PluginManager pm = new DefaultPluginManager(
    rt.pluginRegistry(), rt.extensionRegistry(), rt.eventBus(), ...);
```

## 备选方案对比

| 维度 | A. Builder（CoreRuntime）<br/>⭐ 推荐 | B. Java SPI | C. Spring 可选依赖 | D. 保持现状（ADR-003） |
|------|--------------------------------------|-------------|-------------------|----------------------|
| core 零框架依赖 | ✅ 零依赖 | ✅ 零依赖 | ❌ 依赖 spring-boot-autoconfigure | ✅ 零依赖 |
| core 独立可用 | ✅ `CoreRuntime.defaults()` | ⚠️ 需手动调用 ServiceLoader | ✅ 自动装配 | ❌ 需手动 new 所有 Bean |
| 依赖注入能力 | ✅ 构造器注入 | ❌ SPI 无法表达依赖关系 | ✅ @Autowired | ✅ @Autowired |
| 可覆盖性 | ⭐⭐⭐⭐⭐ Builder 逐字段覆盖 | ⭐⭐ 替换 jar 文件 | ⭐⭐⭐⭐⭐ @ConditionalOnMissingBean | ⭐⭐⭐⭐⭐ @ConditionalOnMissingBean |
| 设计借鉴 | Netty / gRPC / HikariCP | SLF4J / JDBC / JAXP | Spring Boot 自身模式 | — |
| 学习成本 | 极低 | 中 | 低 | 低 |
| 与项目理念一致性 | ✅ 与"微内核"理念一致 | ⚠️ 类加载器问题复杂 | ❌ 违反"技术框架不进核心" | ⚠️ 归属错位 |

**选择 A 的理由总结**：

1. **core 保持零框架依赖**——仅依赖 `java.util.Objects`
2. **core 获得独立可用性**——`CoreRuntime.defaults()` 一行即可
3. **装配逻辑在 core 内部**——谁定义谁配置，内聚正确
4. **Spring 集成由 api 薄桥接**——职责清晰，可替换
5. **业界有大量成功先例**——Netty、gRPC、HikariCP 均使用 Builder 装配

## 覆盖 ADR-003 的决策

| ADR-003（议题六）决策 | 新决策 | 变更原因 |
|----------------------|--------|---------|
| CoreAutoConfig 归属 api 模块 | CoreRuntime 归属 core 模块，Spring 桥接在 api | core 独立可用 + 归属正确 |
| 使用 @Bean + @ConditionalOnMissingBean 逐个装配 | Builder 模式在 core 中装配，桥接层仅委托 | 解耦 Spring，提升复用性 |
| 装配顺序由 @Order/@DependsOn 保证 | 装配顺序由 Builder.build() 的构造逻辑保证 | 构造时注入更安全、更透明 |

保留不变的部分：
- `@ConditionalOnMissingBean` 覆盖机制
- 六个 Bean 的类型和 Bean 名称
- `AuthExtensionConfig`、`ApiAutoConfig`、`BootstrapConfig` 职责不变

## 风险与缓解

| 风险 | 影响 | 可能性 | 缓解措施 |
|------|------|--------|---------|
| CoreRuntime 创建失败（空指针等） | 系统无法启动 | 极低 | Builder.build() 填充全默认，构造器 Objects.requireNonNull 防御；CoreRuntime 逻辑简单无外部依赖 |

## 总结

**核心决策**：

```
┌────────────────────────────────────────────────────┐
│                                                    │
│   CoreRuntime (Builder) → core 模块                 │
│   ├─ 零框架依赖                                      │
│   ├─ 装配逻辑归属正确                                 │
│   ├─ 可独立使用 (非 Spring 项目)                       │
│   └─ Builder 选择性覆盖                               │
│                                                    │
│   CoreAutoConfig (Spring Bridge) → api 模块          │
│   ├─ 薄桥接层（仅委托，不参与创建）                     │
│   ├─ @ConditionalOnMissingBean 保留                  │
│   └─ 向后完全兼容                                     │
│                                                    │
└────────────────────────────────────────────────────┘
```

**关键收益**：
1. core 模块实现真正的"零框架依赖、独立可用"
2. 装配归属从 api 纠正到 core，内聚性提升
3. Spring 集成退化为薄桥接，可随时替换
4. 向后完全兼容，零破坏性变更
5. 修改仅 1 新增 + 1 修改文件，极低风险
