# 依赖治理规范

> 本规范用于指导项目的 Maven 依赖管理，
> 目标是：
>
> - 保证 **项目永久纯净、可演进**
> - 明确各模块对第三方技术的依赖边界
> - 防止在开发过程中随意引入依赖导致架构污染
> - 支持插件化、可替换实现与 AI 原生能力长期扩展

------

## 1. 总体原则（必须遵守）

### 1.1 分层依赖原则

本项目的所有依赖必须严格遵循以下三层治理模型：

| 层级           | 职责             | 说明                                   |
| -------------- | ---------------- | -------------------------------------- |
| **版本治理层** | 统一第三方版本   | 仅在父 POM 的 `<dependencyManagement>` |
| **技术实现层** | 具体框架与中间件 | platform-infra / platform-app          |
| **插件实现层** | 可替换实现       | plugins/*                              |

> ❗ **禁止任何模块“顺手引依赖”而不考虑架构层级。**

------

### 1.2 核心铁律（红线）

1. **platform-core 禁止依赖任何 Spring / ORM / JSON / Redis / AI SDK**
2. **platform-plugin 禁止依赖任何 spring-boot-starter**
3. **dependencyManagement 只管理版本，不等于引入依赖**
4. **所有技术型依赖必须能被插件替换**

违反以上任意一条，视为架构错误。

------

## 2. 父 POM（backend-platform/pom.xml）规范

### 2.1 父 POM 的唯一职责

父 POM 只允许做以下事情：

- 统一第三方依赖版本
- 统一 Java / 编译插件版本
- 统一 Spring Boot BOM（如使用）

❌ 父 POM **禁止直接声明任何 spring-boot-starter 依赖**。

------

### 2.2 dependencyManagement 使用规范

`<dependencyManagement>` 中 **必须** 管理以下项目通用依赖版本（但不自动引入）：

#### 2.2.1 Spring Boot BOM

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-dependencies</artifactId>
  <version>${spring.boot.version}</version>
  <type>pom</type>
  <scope>import</scope>
</dependency>
```

------

#### 2.2.2 项目统一管理的第三方库（必须声明）

以下依赖 **必须在 dependencyManagement 中统一版本**：

- fastjson2
- hutool-all
- druid-spring-boot-starter
- aspectjweaver
- commons-pool2
- jaxb-api
- lombok

示例：

```xml
<dependency>
  <groupId>com.alibaba.fastjson2</groupId>
  <artifactId>fastjson2</artifactId>
  <version>2.0.53</version>
</dependency>
```

> ⚠️ 只声明 version，不声明 scope。

------

## 3. 各模块依赖准入规范（重点）

### 3.1 platform-core（绝对纯净区）

#### ✅ 允许依赖

- JDK 标准库
- Lombok（`scope=provided`，可选）

#### ❌ 严禁依赖

- spring-boot-starter-*
- Spring Framework
- MyBatis / JPA / JDBC
- Redis / MQ
- fastjson / Jackson
- Hutool / Guava
- AI SDK（OpenAI / LangChain 等）

> **Core 只允许定义抽象与规则，不允许接触任何技术实现。**

------

### 3.2 platform-plugin（插件系统内核）

#### ✅ 允许依赖

- platform-core
- JDK 标准库
- Lombok（provided）

#### ❌ 严禁依赖

- spring-boot-starter-*
- ORM / Redis / Web 框架

插件系统必须保持对宿主环境的最小假设。

------

### 3.3 platform-infra（技术适配层）

#### 3.3.1 允许并**要求** Cursor 添加的依赖

以下依赖 **必须由 Cursor 按需添加至 platform-infra/pom.xml**：

- spring-boot-starter-web
- spring-boot-starter-validation
- spring-boot-starter-data-redis
- commons-pool2
- druid-spring-boot-starter
- aspectjweaver
- fastjson2
- jaxb-api
- hutool-all（谨慎使用，仅限 infra）

这些依赖用于：

- Web 适配
- 校验
- 缓存与连接池
- 数据源与 ORM
- AOP 与日志、审计

------

### 3.4 platform-app（启动与装配模块）

#### 3.4.1 允许并**要求** Cursor 添加的依赖

- spring-boot-starter
- spring-boot-starter-logging
- spring-boot-starter-test（scope=test）
- spring-boot-starter-freemarker（如启用模板 / 报表）

platform-app **只负责启动与装配，不承载业务逻辑**。

------

### 3.5 plugins/*（插件实现）

插件依赖规则：

- 只依赖 **platform-core SPI**
- 技术栈自选（Spring / MyBatis / AI SDK 均可）
- 插件对技术栈负责，平台不兜底

> 插件即“可替换实现单元”。

------

## 4. 测试依赖规范

- `spring-boot-starter-test` 只能出现在：
  - platform-app
  - platform-infra
  - plugins/*
- 禁止出现在 platform-core / platform-plugin

------

## 5. 开发约束

1. 禁止在 platform-core 中引入任何第三方技术依赖
2. 所有 Spring Boot Starter 必须放在 platform-infra 或 platform-app
3. 所有版本号必须由父 POM dependencyManagement 管理
4. 新增依赖前必须判断其是否可被插件替换

------

## 6. 架构自检清单（提交前必查）

-  core 是否仍可脱离 Spring 编译？
-  infra 是否只做技术适配、不含业务判断？
-  插件是否只通过 SPI 与 core 交互？
-  是否存在“为了方便直接引依赖”的情况？

若任一项失败，必须回滚修改。

------

## 7. 结语

> **依赖治理是平台架构的生命线。**
>
> 本规范的目标不是限制开发速度，而是确保：
>
> - 三年后仍能替换技术栈
> - AI 能力可持续演进
> - 插件生态不会被核心绑死

所有开发与 AI 自动生成代码，必须严格遵守本规范。
