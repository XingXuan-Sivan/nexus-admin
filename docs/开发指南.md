# admin-panel 插件开发修改指南（含 Web 接入机制，供 Cursor 执行）

------

# 一、任务目标（更新）

在现有插件系统中实现 `admin-panel` 插件，并**接入已完成的 Web 桥接机制**，实现：

```text
1. 管理 REST API（通过插件 Controller 暴露）
2. 最小认证能力（Bootstrap Identity）
3. 插件化认证体系（AuthProvider 扩展）
4. 通过 WebEndpointRegistrar 将 Controller 注册到主容器
5. 不破坏现有 Plugin 生命周期 / 状态机
```

------

# 二、关键约束（新增 Web 约束）

```text
1. Controller 不会自动生效（运行在 PluginContext）
2. 必须通过 WebEndpointRegistrar 注册到 HandlerMapping
3. 不允许手动向 RootContext 注册 Bean
4. Controller 生命周期必须跟随插件生命周期
5. 插件卸载时必须移除所有 Mapping
```

------

# 八、Spring 配置（重要调整）

------

## 8.1 AdminAutoConfiguration（保持）

```java
@Configuration
public class AdminAutoConfiguration {

    @Bean
    public CompositeAuthProvider compositeAuthProvider(List<AuthProvider> providers) {
        return new CompositeAuthProvider(providers);
    }

    @Bean
    public BootstrapAuthProvider bootstrapAuthProvider(ConfigFacade configFacade) {
        return new BootstrapAuthProvider(configFacade);
    }

    @Bean
    public AdminAuthFilter adminAuthFilter(CompositeAuthProvider provider) {
        return new AdminAuthFilter(provider);
    }
}
```

------

## 8.2 不再需要

```text
❌ 不需要手动注册 Controller
❌ 不需要 @ComponentScan
```

# 十三、常见错误（必须避免）

------

## ❌ 错误 1：Controller 不生效

原因：

```text
没有被 PluginContext 扫描
```

------

## ❌ 错误 2：路径冲突

原因：

```text
多个插件使用相同路径
```

解决：

```text
依赖系统自动 prefix
```

------

## ❌ 错误 3：卸载后接口仍存在

原因：

```text
WebEndpointRegistrar 未正确 unregister
```

------

## ❌ 错误 4：直接依赖 core

```text
禁止使用 PluginManager / ConfigManager 实现类
```
