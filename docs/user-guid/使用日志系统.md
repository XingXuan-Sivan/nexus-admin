# 使用日志系统

------

## 1. 概述

平台内建统一的日志系统，为平台和插件提供日志写入、存储、查询与管理能力。开发者无需改变 `log.info()` 的使用习惯，SLF4J 日志自动通过 Logback Appender 汇入平台日志体系，可在管理面板统一查询。

核心特性：

- **零侵入**：SLF4J 日志自动拦截，无需修改现有代码
- **分类筛选**：日志按 `category`（system / audit）和 `typeName`（如 login、api-request）二维分类，支持精确过滤
- **上下文注入**：traceId、userId、tenantId 等上下文信息自动从 MDC 提取
- **可扩展**：插件可通过 `LogType.of()` 创建自定义日志类型，管理面板直接检索

> 管理 API 基础路径：`/admin/v1/logs`，需携带认证令牌。查询接口使用 `system.view` 权限，写入与清理使用 `config.manage` 权限。

------

## 2. 查看日志

### 2.1 分页查询

查询接口支持多种可选过滤条件，返回按时间倒序排列的分页结果：

```bash
curl "http://localhost:8080/admin/v1/logs?page=1&size=20" \
  -H "Authorization: Bearer <your-token>"
```

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "total": 156,
    "page": 1,
    "size": 20,
    "records": [
      {
        "id": "a1b2c3d4-...",
        "timestamp": "2026-06-14T10:30:00Z",
        "type": "audit/login",
        "level": "INFO",
        "message": "用户 admin 登录成功",
        "userId": "admin",
        "traceId": "abc123-...",
        "channelId": "HTTP",
        "attributes": {
          "ip": "192.168.1.1",
          "result": "SUCCESS"
        }
      }
    ]
  }
}
```

## 3. 按条件筛选日志

### 3.1 按分类（category）筛选

| category | 含义 | 包含的典型场景 |
|----------|------|--------------|
| `system` | 平台运行日志 | 插件生命周期、API 请求、配置变更、AI 调用、错误堆栈等 |
| `audit`  | 安全审计日志 | 登录/登出、权限检查、敏感操作留痕 |

```bash
# 查看全部系统运行日志
curl "http://localhost:8080/admin/v1/logs?category=system" \
  -H "Authorization: Bearer <your-token>"

# 查看全部安全审计日志
curl "http://localhost:8080/admin/v1/logs?category=audit" \
  -H "Authorization: Bearer <your-token>"
```

### 3.2 按子类型（typeName）精确筛选

在 category 基础上叠加 typeName 进行精确筛选：

```bash
# 仅查看登录相关审计日志
curl "http://localhost:8080/admin/v1/logs?category=audit&typeName=login" \
  -H "Authorization: Bearer <your-token>"

# 查看插件生命周期日志
curl "http://localhost:8080/admin/v1/logs?category=system&typeName=plugin-lifecycle" \
  -H "Authorization: Bearer <your-token>"

# 查看 API 请求日志
curl "http://localhost:8080/admin/v1/logs?category=system&typeName=api-request" \
  -H "Authorization: Bearer <your-token>"
```

内置常用 typeName：

| category | typeName | 含义 |
|----------|----------|------|
| `system` | `general` | 系统通用日志 |
| `system` | `plugin-lifecycle` | 插件生命周期事件 |
| `system` | `api-request` | API 请求/响应 |
| `system` | `config-change` | 配置变更 |
| `system` | `ai-call` | AI 调用 |
| `audit`  | `general` | 审计通用日志 |
| `audit`  | `login` | 登录事件 |
| `audit`  | `permission` | 权限检查 |
| `audit`  | `operation` | 用户敏感操作 |

### 3.3 按级别筛选

```bash
# 仅查看 ERROR 级别日志
curl "http://localhost:8080/admin/v1/logs?level=ERROR" \
  -H "Authorization: Bearer <your-token>"

# 查看审计分类下的 WARN 级别日志
curl "http://localhost:8080/admin/v1/logs?category=audit&level=WARN" \
  -H "Authorization: Bearer <your-token>"
```

### 3.4 关键字搜索

关键字匹配日志消息内容（`message` 字段）：

```bash
curl "http://localhost:8080/admin/v1/logs?keyword=登录失败" \
  -H "Authorization: Bearer <your-token>"
```

### 3.5 时间范围筛选

```bash
# 最近一小时的日志
curl "http://localhost:8080/admin/v1/logs?from=2026-06-14T09:00:00Z&to=2026-06-14T10:00:00Z" \
  -H "Authorization: Bearer <your-token>"
```

### 3.6 组合筛选

所有参数可自由组合：

```bash
# API 请求中的 ERROR 级别日志，时间范围限定
curl "http://localhost:8080/admin/v1/logs?category=system&typeName=api-request&level=ERROR&from=2026-06-14T00:00:00Z&to=2026-06-14T23:59:59Z&page=1&size=50" \
  -H "Authorization: Bearer <your-token>"
```

## 4. 管理保留策略

### 4.1 查看当前策略

```bash
curl "http://localhost:8080/admin/v1/logs/retention" \
  -H "Authorization: Bearer <your-token>"
```

响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "defaultRetention": "PT720H",
    "auditRetention": "PT2160H",
    "errorRetention": "PT4320H",
    "autoCleanup": true
  }
}
```

字段说明：

| 字段 | 格式 | 说明 |
|------|------|------|
| `defaultRetention` | ISO 8601 Duration | 普通日志保留期限，默认 30 天（PT720H） |
| `auditRetention` | ISO 8601 Duration | 审计日志保留期限，默认 90 天（PT2160H） |
| `errorRetention` | ISO 8601 Duration | 错误日志保留期限，默认 180 天（PT4320H） |
| `autoCleanup` | boolean | 是否启用自动清理 |

### 4.2 更新策略

```bash
curl -X PUT "http://localhost:8080/admin/v1/logs/retention" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-token>" \
  -d '{
    "defaultRetention": "PT1440H",
    "auditRetention": "PT4320H",
    "errorRetention": "PT8760H",
    "autoCleanup": true
  }'
```

> 此操作需要 `config.manage` 权限。

------

## 5. 清理过期日志

手动触发过期日志清理：

```bash
curl -X POST "http://localhost:8080/admin/v1/logs/cleanup" \
  -H "Authorization: Bearer <your-token>"
```

响应返回清理的日志条数：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": 42
}
```

> 此操作需要 `config.manage` 权限。

## 6. 在插件中写入日志

### 6.1 通过 SLF4J 隐式写入（推荐）

开发者在插件中使用 `log.info()` 即可，日志自动通过 Logback Appender 汇入平台体系：

```java
@Slf4j
public class MyPlugin extends AbstractPlugin {

    @Override
    protected void start() throws Exception {
        log.info("插件启动完成，开始初始化业务模块");
        // 业务逻辑 ...
    }
}
```

所有 `AbstractPlugin` 子类自动在生命周期方法中输出日志（初始化/启动/停止/卸载），无需手动添加。

### 6.2 通过 LogWriter 显式写入结构化日志

当需要精确控制日志类型和属性时，通过 `LogWriter` 扩展点显式写入：

```java
@Autowired
private LogWriter logWriter;

@Autowired
private InvocationContext context;

public void handleOrderCreated(String orderId) {
    LogEntry entry = LogEntry.builder()
            .type(LogType.of("system", "order-created"))
            .level(LogLevel.INFO)
            .message("订单创建成功: #" + orderId)
            .userId(context.userId())
            .attribute("orderAmount", "299.00")
            .build();
    logWriter.write(entry, context);
}
```

### 6.3 使用 LogFactory 工厂类

平台为内置常用日志类型提供了 `SystemLogFactory` 和 `AuditLogFactory` 工厂类，封装了标准属性键常量和语义化构建方法：

```java
// 记录配置变更
LogEntry configEntry = SystemLogFactory.configChange(
        "panel.log.max-entries", "10000", "20000");
logWriter.write(configEntry, context);

// 记录登录成功
LogEntry loginEntry = AuditLogFactory.loginSuccess("admin", "192.168.1.100");
logWriter.write(loginEntry, context);

// 记录权限拒绝
LogEntry denyEntry = AuditLogFactory.permissionDenied(
        "user1", "/admin/v1/config", "write");
logWriter.write(denyEntry, context);
```

## 7. 创建自定义日志类型

插件可通过 `LogType.of()` 创建自定义日志类型，无需修改核心代码：

```java
// 创建业务专属日志类型
LogType ORDER_EVENT = LogType.of("system", "order-created");
LogType DATA_EXPORT = LogType.of("audit", "data-export");

// 写入自定义类型日志
LogEntry entry = LogEntry.builder()
        .type(ORDER_EVENT)
        .level(LogLevel.INFO)
        .message("订单创建: #" + orderId)
        .userId(context.userId())
        .build();
logWriter.write(entry, context);
```

自定义类型在管理面板中与内置类型同等对待，直接通过字符串检索：

```bash
# 检索自定义日志类型
curl "http://localhost:8080/admin/v1/logs?category=system&typeName=order-created" \
  -H "Authorization: Bearer <your-token>"

curl "http://localhost:8080/admin/v1/logs?category=audit&typeName=data-export" \
  -H "Authorization: Bearer <your-token>"
```

> category 只能为 `system` 或 `audit`（遵循平台的二维分类体系），typeName 可自由命名。

## 8. 通过 MDC 路由日志类型

对于通过 SLF4J `log.info()` 输出的日志，可通过 MDC 键 `logType` 动态指定日志类型，替代默认的 `system/general`：

```java
// 标记后续日志为审计登录类型
MDC.put("logType", "audit/login");
log.info("用户 {} 登录成功", userId);
MDC.remove("logType");

// 标记为 API 请求日志
MDC.put("logType", "system/api-request");
log.info("GET /admin/v1/plugins → 200 (12ms)");
MDC.remove("logType");

// 标记为自定义业务日志类型
MDC.put("logType", "system/order-created");
log.info("订单创建: #{}", orderId);
MDC.remove("logType");
```

`logType` 值的格式为 `"category/typeName"`，未设置时默认为 `system/general`。

平台已在 `AuthFilter` 中将登录日志自动标记为 `audit/login`，插件无需重复设置。

### 上下文注入

以下 MDC 键会被 Logback Appender 自动提取并注入日志条目：

| MDC 键 | 对应 LogEntry 字段 | 说明 |
|--------|------------------|------|
| `traceId` | traceId | 链路追踪 ID，在 AuthFilter 中自动生成 |
| `userId` | userId | 当前用户标识 |
| `tenantId` | tenantId | 租户标识 |
| `channelId` | channelId | 调用渠道（如 HTTP、GRPC） |
| `logType` | type | 日志类型路由，格式 `category/typeName` |

在 Filter/Interceptor 中写入上下文后，所有后续 SLF4J 日志自动携带这些信息：

```java
MDC.put("traceId", UUID.randomUUID().toString());
MDC.put("userId", authResult.userId());
MDC.put("channelId", "HTTP");
try {
    chain.doFilter(request, response);
} finally {
    MDC.clear();
}
```

## 9. 配置属性

日志系统通过 `application.yml` 配置：

```yaml
panel:
  log:
    max-entries: 10000          # 内存存储最大条目数（默认 10000）
    auto-cleanup: true          # 是否启用自动清理（默认 true）
    cleanup-cron: "0 0 3 * * ?" # 自动清理 Cron 表达式
```
