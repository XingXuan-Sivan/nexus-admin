# 使用配置中心

------

## 1. 配置中心概述

配置中心为平台和插件提供统一的配置管理能力，支持配置读写、热更新和 Schema 驱动的配置定义。

------

## 2. 访问配置

### 2.1 在插件中访问配置

```java
public class MyPlugin implements Plugin {

    @Override
    public void onStart(PluginContext context) throws Exception {
        ConfigManager config = context.platform().config();
        
        // 获取配置值（scope 为插件ID）
        Optional<String> value = config.get("my-plugin", "timeout");
        
        // 获取类型化配置
        Optional<Integer> timeout = config.get("my-plugin", "timeout", Integer.class);
        
        // 设置配置值
        config.set("my-plugin", "timeout", "60");
    }
}
```

### 2.2 配置 Scope 规范

| Scope | 说明 | 示例 |
|-------|------|------|
| platform | 平台级配置 | platform.coreVersion |
| platform.disabled | 插件禁用配置 | platform.disabled.disabled-plugins |
| {pluginId} | 插件私有配置 | order-plugin.timeout |

------

## 3. 默认配置文件路径

### 3.1 配置存储目录

默认配置存储在 `plugins-data/config/` 目录下：

```
plugins-data/
└── config/
    ├── platform.yml              # 平台配置
    ├── disabled.yml              # 插件禁用配置
    └── {pluginId}.yml            # 插件配置
```

### 3.2 插件默认配置

插件可在 `META-INF/config.yml` 中定义默认配置：

```yaml
timeout: 30
enableAutoRetry: true
maxConnections: 100
```

### 3.3 配置优先级

配置按以下优先级解析（高到低）：

1. **环境变量**：`NEXUS_{scope}_{key}`（如 `NEXUS_PLUGIN_ORDER_TIMEOUT`）
2. **文件配置**：`plugins-data/config/*.yml`
3. **插件默认配置**：`META-INF/config.yml`

------

## 4. 定义配置 Schema

### 4.1 插件 Schema

在 `META-INF/schema.yml` 中定义插件配置结构：

```yaml
pluginId: my-plugin
properties:
  timeout:
    type: integer
    title: 超时时间
    description: 请求超时时间（秒）
    default: 30
    minimum: 1
    maximum: 3600
  enableAutoRetry:
    type: boolean
    title: 自动重试
    default: true
  logLevel:
    type: enum
    title: 日志级别
    enum: [DEBUG, INFO, WARN, ERROR]
    default: INFO
```

### 4.2 平台 Schema

平台配置 Schema 定义在 core 模块中：

| 文件路径 | 说明 |
|----------|------|
| `META-INF/schema/platform.yml` | 平台基础配置 Schema |
| `META-INF/schema/platform-disabled.yml` | 平台禁用配置 Schema |

平台 Schema 由多个子作用域合并而成，对外统一为 `schemaId = "platform"`。子作用域的属性键会添加前缀，例如 `platform.disabled` 的 `disabled-plugins` 在合并后变为 `disabled.disabled-plugins`。

获取平台 Schema：

```java
// 获取平台 Schema 定义
Optional<ConfigSchema> platformSchema = config.getPlatformSchema();

// 构建平台 UI Schema
Map<String, Object> uiSchema = config.buildPlatformUISchema();
```

### 4.3 Schema 字段说明

| 字段 | 说明 |
|------|------|
| type | 数据类型：integer、boolean、string、enum、number |
| title | 配置项显示名称 |
| description | 配置项描述 |
| default | 默认值 |
| minimum | 最小值（数值类型） |
| maximum | 最大值（数值类型） |
| enum | 枚举值列表 |
| required | 是否必填 |

## 5. 监听配置变更

### 5.1 实现 ConfigListener

```java
public class MyPlugin implements Plugin, ConfigListener {

    @Override
    public void onStart(PluginContext context) throws Exception {
        // 注册监听器
        context.platform().config().addListener(this);
    }

    @Override
    public void onConfigChanged(ConfigChangedEvent event) {
        if (event.scope().equals("my-plugin")) {
            System.out.println("配置变更: " + event.key() + 
                " = " + event.value() + " (旧值: " + event.oldValue() + ")");
        }
    }

    @Override
    public String interestedScope() {
        return "my-plugin";  // 只监听本插件配置
    }
}
```

### 5.2 通过事件总线监听

```java
eventBus.subscribe(ConfigChangedEvent.class, event -> {
    System.out.println("配置变更: " + event.fullKey());
});
```

## 6. 扩展配置存储

### 6.1 实现 ConfigStore 接口

默认使用文件存储，可扩展为数据库或远程配置中心：

```java
public class DatabaseConfigStore implements ConfigStore {

    @Override
    public Optional<String> get(String scope, String key) {
        // 从数据库读取配置
        return configRepository.findValue(scope, key);
    }

    @Override
    public Map<String, Object> getScope(String scope) {
        // 获取指定作用域的完整配置
        return configRepository.findScope(scope);
    }

    @Override
    public void set(String scope, String key, Object value) {
        // 写入数据库
        configRepository.saveValue(scope, key, value);
    }

    @Override
    public void setAll(String scope, Map<String, Object> config) {
        // 批量写入配置
        configRepository.saveScope(scope, config);
    }

    @Override
    public void remove(String scope, String key) {
        configRepository.deleteValue(scope, key);
    }

    @Override
    public boolean exists(String scope, String key) {
        return configRepository.exists(scope, key);
    }

    @Override
    public void invalidateCache(String scope) {
        // 数据库存储无需缓存失效
    }

    @Override
    public void invalidateAllCache() {
        // 数据库存储无需缓存失效
    }
}
```

### 6.2 注册自定义存储

自定义存储通过构造函数传入，需在创建 ConfigManager 时指定：

```java
ConfigStore dbStore = new DatabaseConfigStore(dataSource);
DefaultConfigManager configManager = new DefaultConfigManager(
    resolver, schemaRegistry, dbStore, eventBus
);
```

## 7. 扩展配置源

### 7.1 实现 ConfigSource 接口

添加新的配置来源，如远程配置中心：

```java
public class RemoteConfigSource implements ConfigSource {

    @Override
    public Optional<String> get(String scope, String key) {
        // 从远程配置中心获取
        return remoteConfigClient.getValue(scope + "." + key);
    }

    @Override
    public int priority() {
        return 5;  // 高优先级（数值越小优先级越高）
    }

    @Override
    public String name() {
        return "Remote";
    }
}
```

### 7.2 注册配置源

```java
configManager.registerSource(new RemoteConfigSource(configServerUrl));
```

## 8. 配置绑定

### 8.1 自动绑定到对象

将配置自动绑定到 Java 对象字段：

```java
public class MyPluginConfig {
    private int timeout = 30;
    private boolean enableAutoRetry = true;
    // getters/setters
}

// 绑定配置
PluginConfigBinder binder = new PluginConfigBinder(configManager);
binder.bind("my-plugin", config);
```

### 8.2 配置热更新

配置变更时自动重新绑定：

```java
ConfigListener listener = binder.createListener("my-plugin");
configManager.addListener(listener);
```

------

## 9. 注意事项

- Schema 和默认配置文件（schema.yml、config.yml）均为可选
- 配置变更会触发 ConfigChangedEvent 事件
- 插件禁用状态通过配置持久化，重启后保持
- 自定义存储和配置源需在插件启动前注册
- 平台 Schema 由多个子作用域合并而成，属性键可能带有前缀
