# 使用配置中心

## 1. 配置中心管理什么

配置中心用于运行期可调整的平台策略和插件配置。以下内容仍是启动期静态配置，不通过配置中心热修改：

- `server.port`、`spring.*`、日志框架启动参数。
- 插件目录、数据目录、运行模式等文件系统和加载策略。
- `panel.auth.bootstrap-password` 等启动认证兜底参数。

管理面板通过顶层“配置中心”菜单进入。插件列表中的“配置”用于快速修改单个插件；配置中心还提供配置域目录、值来源、Schema 和受控原始文档。

## 2. 配置域

平台内置域：

| scopeId | 说明 |
|---|---|
| `platform` | 平台运行期信息和插件策略 |
| `platform.disabled` | 插件禁用集合，由插件管理功能维护 |

插件域直接使用 `plugin.json` 中的原始 `pluginId`。例如插件 `demo-plugin` 的 scopeId 就是 `demo-plugin`，不是 `plugin.demo-plugin` 或 `plugin:demo-plugin`。

scopeId 由服务端目录接口返回。客户端和插件管理界面只透传，不通过前缀、点号或其他字符推导层级。

插件 ID 必须使用小写规范 `[a-z][a-z0-9_-]*(?:\.[a-z0-9_-]+)*`，最长 128 个字符；`platform` 和 `platform.disabled` 是平台保留 ID，插件不能声明或注册。

## 3. 配置来源与优先级

有效值按下列顺序解析：

```text
环境变量 > 持久化文件 > 插件默认配置
```

### 3.1 环境变量

命名格式：

```text
PANEL_{SCOPE}_{KEY}
```

scope 和 key 转为大写，点号与连字符转为下划线。例如：

```text
scope: demo-plugin
key: connection.timeout
环境变量: PANEL_DEMO_PLUGIN_CONNECTION_TIMEOUT
```

环境变量优先级最高。即使在管理面板保存了文件层值，当前有效值仍可能不变；snapshot 会将字段标记为 `source=environment` 和 `effectiveValueOverridden=true`。

### 3.2 持久化文件

默认目录是 `{plugin.data-path}/config`：

```text
config/
├── platform.yml
├── platform.disabled.yml
├── demo-plugin.yml
└── system-user.yml
```

不要在插件代码中直接操作这些文件，应通过 `ConfigManager` 或管理 API 修改，以获得 revision、原子写入、缓存刷新和变更事件。

### 3.3 插件默认配置

插件可以提供 `META-INF/config.yml`：

```yaml
greetingMessage: Hello from Demo Plugin!
enableFeature: true
maxItems: 100
```

Schema 中的 `default` 也属于默认层；同一路径同时存在时，`config.yml` 覆盖 Schema default。重置配置只删除持久化 override，不把默认值复制进文件。

## 4. 定义插件 Schema

插件在 `META-INF/schema.json` 提供 JSON Schema Draft 2020-12：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "urn:example:config:demo-plugin",
  "type": "object",
  "additionalProperties": false,
  "x-ui-groups": {
    "general": { "title": "基础配置", "order": 10 },
    "advanced": { "title": "高级配置", "order": 90, "collapsible": true }
  },
  "properties": {
    "greetingMessage": {
      "type": "string",
      "title": "问候语",
      "default": "Hello",
      "minLength": 1,
      "maxLength": 200,
      "x-ui-group": "general"
    },
    "maxItems": {
      "type": "integer",
      "title": "最大项目数",
      "default": 100,
      "minimum": 1,
      "maximum": 1000,
      "x-ui-group": "advanced",
      "x-ui-options": { "widget": "slider", "unit": "项" }
    }
  },
  "required": ["greetingMessage"]
}
```

后端按 JSON Schema Draft 2020-12 接收、保留并校验 Schema；管理面板的可视化编辑器只实现经过验证的安全子集。当前可视化支持 object 根、基础类型、嵌套 object、普通 array、`if/then/else`、`$defs` 与明确可合并的本地 `$ref`，并遵循以下降级边界：

- 复杂 `allOf`、`anyOf`、非枚举型 `oneOf`、`dependentRequired`、`dependentSchemas`、歧义约束合并和条件数组项会显示路径级诊断，受影响对象或字段只读。
- `date`、`date-time`、`time`、`email`、`uri` 是当前已识别的 `format`；其他格式显示诊断并将对应字段设为只读。
- `additionalProperties` 中已有的动态键和值会以只读字段或 JSON 保留展示，但可视化模式不提供新增、改名或删除。只有域允许配置文件模式时，才能直接从原始文档修改。
- 远程 `$ref` 被服务端拒绝。Schema 只描述数据和显示提示，不能加载脚本、远程组件或 HTML。

常用 `x-ui-options`：

| 字段 | 说明 |
|---|---|
| `widget` | `input/textarea/password/color/select/radio/slider/switch/checkbox/date/date-time/time` |
| `order` | 分组内排序 |
| `span` | 桌面 24 栅格跨度 |
| `advanced` | 快速配置中默认放入高级项 |
| `unit` | 安全文本单位 |
| `sensitive` | 标记敏感字段 |
| `restartRequired` | 修改后提示需重启 |

## 5. 敏感配置

敏感字段使用标准 `writeOnly`，并可同时提供 UI 提示：

```json
{
  "type": "string",
  "title": "访问令牌",
  "writeOnly": true,
  "minLength": 12,
  "x-ui-options": {
    "widget": "password",
    "sensitive": true
  }
}
```

安全规则：

- Schema 不得为密码、Token 等提供可用明文 default。
- snapshot 不返回敏感有效值、持久化值或默认值，只显示是否已设置。
- 修改敏感值使用 `replace-sensitive`，不要把掩码字符串重新提交。
- 清除敏感值使用 `clear-sensitive`；普通 `set/unset` 会被服务端拒绝。配置重置会在服务端自动采用受控清除语义。
- 敏感替换、清除以及会清除敏感值的重置要求 `config.secret.rotate`；该权限不授予读取敏感明文的能力。
- `$ref` sibling、组合 Schema 和父对象内的敏感后代都按敏感路径处理，不能通过提交整个父对象绕过。
- 数组 item 中只要含敏感字段，整个数组按一个敏感值处理：snapshot 完整省略，修改时对数组路径使用 `replace-sensitive/clear-sensitive`。
- 普通对象不会仅因含敏感后代而整体变成原子敏感值：父对象 `set/unset` 会被拒绝，非敏感叶子仍可普通修改，敏感叶子必须逐路径使用 `replace-sensitive/clear-sensitive`。
- 日志、事件、校验问题和冲突响应不包含旧值或新值。
- 当前平台没有近期重新认证机制，因此含敏感字段的原始配置文档只返回脱敏锁定状态，不能通过 document 接口读写。

引导认证不再提供代码内默认密码。首次启动应通过静态启动配置或环境变量注入：

```yaml
panel:
  auth:
    bootstrap-password: ${PANEL_BOOTSTRAP_PASSWORD:}
```

未配置密码时，引导密码认证不会使用通用默认口令。

## 6. 在插件代码中读取配置

插件通过上下文中的 `ConfigManager` 读取：

```java
String message = context.platform().config()
        .get("demo-plugin", "greetingMessage")
        .orElse("Hello");

int maxItems = context.platform().config()
        .get("demo-plugin", "maxItems", Integer.class)
        .orElse(100);
```

插件应使用自身原始 pluginId，不构造其他 scope 前缀。需要响应热更新时注册 `ConfigListener`，并在卸载时移除监听器；也可以使用 `PluginConfigBinder` 完成对象重绑。

## 7. 管理面板保存语义

### 7.1 可视化配置

可视化编辑使用 JSON Pointer change：

```json
{
  "changes": [
    { "op": "set", "path": "/maxItems", "value": 120 },
    { "op": "unset", "path": "/legacyFlag" }
  ],
  "reason": "调整容量"
}
```

保存前客户端可调用 validate，服务端在真正保存时仍会再次校验。服务端既校验准备持久化的默认值与文件值，也校验应用环境变量等外部来源后的有效值，因此环境变量不会掩盖非法文件配置。所有修改携带 snapshot 的 revision；若其他会话先保存，当前请求收到 409，需重新加载后决定如何处理草稿。

页面返回的 `capabilities` 以及插件列表中的 `canView/canEdit` 均按当前登录用户实时计算。前端应据此隐藏或禁用操作，但服务端仍会独立执行权限校验。

### 7.2 原始文档

非敏感域可以读取和修改 YAML 或 JSON，最大 524288 字节。服务端不接受文件路径，只接受 scopeId。保存时执行安全解析、Schema 校验、同 scope 锁、备份和原子替换。

- document 模式按提交文本原样保存，YAML 注释可以保留。
- structured 模式按数据树生成 YAML，不保证保留原始注释和字段布局。
- `.bak` 是服务端故障恢复副本，不是配置版本历史。

## 8. 常见问题

### 保存成功后为什么有效值没有变化？

检查字段来源。如果 `source=environment`，环境变量覆盖了刚保存的文件层值。移除或调整环境变量并重启相应运行环境后才会改变有效值。

### 为什么没有可视化表单？

该域没有有效的 `META-INF/schema.json`。无 Schema 域仍可查看持久化 snapshot；只有满足 document capability 且不含敏感字段时才能使用原始文档编辑。

### 为什么原始文档被锁定？

Schema 含敏感字段，而平台当前没有近期重新认证能力。请使用可视化表单替换敏感字段；这是服务端安全策略，不能通过前端绕过。

### revision 冲突如何处理？

重新加载最新 snapshot/document，比较本地草稿与服务端值后重新提交。服务端不支持“最后写入者获胜”的静默覆盖。
