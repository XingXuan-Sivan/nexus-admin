# 使用事件总线

------

## 1. 事件作用域

事件系统使用作用域机制实现事件的隔离与路由。每个事件都携带一个作用域，订阅者通过作用域匹配器控制接收哪些事件。

### 1.1 标准作用域

| 作用域 | 说明 | 使用场景 |
|--------|------|----------|
| global | 全局作用域 | 所有订阅者可见的系统级事件 |
| platform | 平台作用域 | 平台核心功能、平台生命周期事件 |
| plugin:{id} | 插件作用域 | 特定插件的私有事件 |
| tenant:{id} | 租户作用域 | 多租户场景下的租户级事件 |

### 1.2 创建作用域

```java
// 全局作用域
EventScope.global()

// 平台作用域
EventScope.platform()

// 插件作用域
EventScope.plugin("system-user")

// 租户作用域
EventScope.tenant("tenant-001")
```

## 2. 订阅事件

### 2.1 基本订阅

订阅所有作用域的事件：

```java
eventBus.subscribe(PluginStateChangedEvent.class, event -> {
    System.out.println("插件 " + event.plugin().getPluginId() + 
                       " 状态变更: " + event.from() + " -> " + event.to());
});
```

### 2.2 按作用域订阅

订阅指定作用域的事件：

```java
// 订阅平台作用域的插件状态变更事件
eventBus.subscribe(
    PluginStateChangedEvent.class,
    event -> {
        System.out.println("插件 " + event.plugin().getPluginId() + 
                           " 状态变更: " + event.from() + " -> " + event.to());
    },
    EventScopeMatcher.platform(),
    null  // 订阅者所属插件ID，可选
);
```

### 2.3 订阅本插件的事件

插件订阅自身作用域的事件：

```java
eventBus.subscribe(
    MyPluginEvent.class,
    event -> { /* 处理事件 */ },
    EventScopeMatcher.plugin("my-plugin"),
    "my-plugin"  // 订阅者所属插件ID
);
```

### 2.4 使用组合匹配器

```java
// 订阅平台作用域或本插件作用域的事件
EventScopeMatcher matcher = EventScopeMatcher.platform()
    .or(EventScopeMatcher.plugin("my-plugin"));

eventBus.subscribe(
    MyEvent.class,
    event -> { /* 处理事件 */ },
    matcher,
    "my-plugin"
);
```

## 3. 发布事件

### 3.1 定义带作用域的事件

```java
// 定义自定义事件，指定作用域
public class MyCustomEvent extends Event {
    private final String message;
    
    public MyCustomEvent(String pluginId, String message) {
        super(EventScope.plugin(pluginId));  // 使用插件作用域
        this.message = message;
    }
    
    public String getMessage() {
        return message;
    }
}
```

### 3.2 发布事件

```java
// 发布事件
eventBus.publish(new MyCustomEvent("my-plugin", "Hello World"));
```

### 3.3 在插件中发布事件

```java
public class MyPlugin implements Plugin {

    @Override
    public void onStart(PluginContext context) throws Exception {
        // 发布本插件作用域的事件
        EventScope scope = EventScope.plugin(context.descriptor().id());
        MyCustomEvent event = new MyCustomEvent(scope, "插件启动完成");
        context.platform().events().publish(event);
    }
}
```

## 4. 监听特定事件

### 4.1 监听插件状态变更

```java
eventBus.subscribe(
    PluginStateChangedEvent.class,
    event -> {
        if (event.isEntering(PluginState.ACTIVE)) {
            System.out.println("插件 " + event.plugin().getPluginId() + " 已启动");
        }
    },
    EventScopeMatcher.platform(),
    null
);
```

### 4.2 监听批处理阶段

```java
eventBus.subscribe(
    PluginProcessEvent.class,
    event -> {
        if (event.phase() == PluginProcessEvent.Phase.LOAD && 
            event.stage() == PluginProcessEvent.Stage.END) {
            System.out.println("加载完成，共 " + event.count() + " 个插件");
        }
    },
    EventScopeMatcher.platform(),
    null
);
```

### 4.3 监听失败事件

```java
eventBus.subscribe(
    PluginFailureEvent.class,
    event -> {
        System.err.println("插件 " + event.pluginId() + " 处理失败: " + 
                           event.error().getMessage());
    },
    EventScopeMatcher.platform(),
    null
);
```

## 5. 注销监听器

### 5.1 手动注销

```java
// 创建监听器引用
EventListener<PluginStateChangedEvent> listener = event -> {
    // 处理逻辑
};

// 订阅
eventBus.subscribe(
    PluginStateChangedEvent.class,
    listener,
    EventScopeMatcher.platform(),
    null
);

// 注销
eventBus.unsubscribe(listener);
```

### 5.2 自动清理

插件卸载时会自动清理其订阅的所有监听器，无需手动处理。

## 6. 常见使用场景

### 6.1 日志记录

```java
eventBus.subscribe(
    PluginStateChangedEvent.class,
    event -> {
        logger.info("Plugin {} state changed: {} -> {}", 
            event.plugin().getPluginId(), event.from(), event.to());
    },
    EventScopeMatcher.platform(),
    null
);
```

### 6.2 监控告警

```java
eventBus.subscribe(
    PluginFailureEvent.class,
    event -> {
        alertService.sendAlert("Plugin failed: " + event.pluginId(), event.error());
    },
    EventScopeMatcher.platform(),
    null
);
```

### 6.3 审计追踪

```java
eventBus.subscribe(
    PluginStateChangedEvent.class,
    event -> {
        auditLog.record(event.plugin().getPluginId(), 
            "STATE_CHANGE", event.from() + " -> " + event.to());
    },
    EventScopeMatcher.platform(),
    null
);
```

### 6.4 插件间通信

```java
// 插件A发布事件
public class PluginA implements Plugin {
    @Override
    public void onStart(PluginContext context) {
        EventScope scope = EventScope.plugin(context.descriptor().id());
        context.platform().events().publish(new DataChangedEvent(scope, data));
    }
}

// 插件B订阅事件
public class PluginB implements Plugin {
    @Override
    public void onStart(PluginContext context) {
        EventBus eventBus = context.platform().events();
        eventBus.subscribe(
            DataChangedEvent.class,
            event -> { /* 处理数据变更 */ },
            EventScopeMatcher.plugin("plugin-a"),  // 订阅插件A的事件
            context.descriptor().id()
        );
    }
}
```

------

## 7. 注意事项

- **监听器应快速处理事件**，避免阻塞事件总线
- **耗时操作应异步执行**或使用独立线程
- **显式指定作用域**，确保事件路由到正确的接收者
- **使用合适的匹配器**，避免接收不必要的事件
- **插件卸载时会自动清理**其订阅的监听器
- **支持手动注销监听器**，避免内存泄漏
