# 插件加载层职责收敛重构说明

**适用对象：Cursor 自动重构执行**
**目标：将“插件来源判定职责”完全收敛至 Discovery 层，Loader 仅承担运行时加载职责**
**约束：不得破坏既有三层装配层级结构**

------

# 一、重构背景

当前项目存在：

- `ClasspathPluginLoader`
- `JarPluginLoader`

这些 Loader 实现同时承担：

- 来源判定
- 路径合法性校验
- classpath 组装
- 实例化插件

这违反系统既定分层设计：

```
1. PluginDiscoverer
2. PluginResolver
3. PluginLoader
```

根据架构约束：

- Loader 只能装配一个实现
- Loader 无子组件
- Loader 只负责将“已解析好的 PluginMetadata”转为 PluginWrapper

因此必须清理 Loader 中所有“来源判断”与“路径判断”职责。

------

# 二、重构总体原则

## 必须满足

- 保持三层结构完全不变
- 不引入新的层级
- 不改变装配关系
- 不改变 PluginManager 外部调用方式
- 不影响 PluginResolver 的职责

## 重构后语义

### PluginDiscoverer

负责：

- 从多个 PluginSource 发现候选插件
- 使用 PluginDescriptorFinder 找 descriptor
- 使用 PluginDescriptorParser 解析 descriptor
- 构建完整 PluginMetadata（包括来源信息）

### PluginResolver

负责：

- 版本冲突处理
- 依赖关系处理
- 归一化 PluginMetadata

### PluginLoader

仅负责：

- 使用 PluginMetadata
- 创建 ClassLoader
- 实例化主类
- 构建 PluginWrapper

------

# 三、具体修改步骤

------

# 步骤一：删除来源耦合型 Loader

删除以下类：

```
ClasspathPluginLoader
JarPluginLoader
```

删除后确保：

- PluginLoader 接口不变（内部方法需要修改）
- 仅保留一个 DefaultPluginLoader 实现

------

# 步骤二：强化 PluginSource 职责

## 修改 PluginSource 接口

必须具备：

```java
public interface PluginSource {

    SourceType getType();

    URL[] getClasspath();

}
```

要求：

- getClasspath() 返回完整可用于 ClassLoader 的 URL[]
- PluginSource 内部负责来源合法性校验
- PluginSource 内部负责路径存在性校验

Loader 不得再做任何路径判断。

------

## 各 Source 实现应包含：

### JarPluginSource

负责：

- 校验 jar 是否存在
- 校验是否为合法 jar
- 返回单一 jar URL

### DirectoryPluginSource

负责：

- 校验目录存在
- 校验目录结构合法
- 返回目录 URL

------

# 步骤三：调整 PluginMetadata

确保 PluginMetadata 包含：

```java
private PluginSource source;
```

要求：

- PluginDiscoverer 构建 PluginMetadata 时必须注入 source
- PluginResolver 不得修改 source
- Loader 必须通过 metadata.getSource() 获取 classpath

------

# 步骤四：重写 DefaultPluginLoader

唯一实现如下：

```java
public class DefaultPluginLoader implements PluginLoader {

    @Override
    public PluginWrapper load(PluginMetadata metadata) {

        try {
            URL[] urls = metadata.getSource().getClasspath();

            ClassLoader parent = getParentClassLoader();

            URLClassLoader classLoader =
                    new URLClassLoader(urls, parent);

            Class<?> pluginClass =
                    classLoader.loadClass(metadata.getMainClass());

            Plugin plugin =
                    (Plugin) pluginClass.getDeclaredConstructor().newInstance();

            return new PluginWrapper(metadata, plugin, classLoader);

        } catch (Exception e) {
            throw new PluginLoadException(metadata.getPluginId(), e);
        }
    }

    protected ClassLoader getParentClassLoader() {
        return Thread.currentThread().getContextClassLoader();
    }
}
```

注意：

- 不允许根据 SourceType 分支判断
- 不允许出现 if (jar) / if (classpath)
- 不允许校验文件路径

------

# 步骤五：保证 Discoverer 承担来源责任

在 PluginDiscoverer 实现中：

1. 遍历所有 PluginSource
2. 从 Source 获取候选路径
3. 使用 DescriptorFinder 找 descriptor
4. 使用 DescriptorParser 构建 descriptor
5. 构建 PluginMetadata（包含 source）

示意流程：

```
PluginSource → DescriptorFinder → DescriptorParser → PluginMetadata
```

禁止：

- Loader 参与 descriptor 解析
- Loader 参与路径合法性判断

------

# 步骤六：保持 Resolver 结构不变

PluginResolver 结构必须保持：

```
PluginResolver
    ├── VersionManager
    └── DependenceManager
```

Resolver 只对：

- 版本
- 依赖
- 冲突

进行处理。

不得触碰 source。

------

# 四、重构后分层语义图

```
PluginManager
    ↓
PluginDiscoverer
    ├── PluginSource (多实现)
    ├── PluginDescriptorFinder (多实现)
    └── PluginDescriptorParser (多实现)
    ↓
PluginResolver
    ├── VersionManager
    └── DependenceManager
    ↓
PluginLoader (唯一实现)
```

------

# 五、校验清单（Cursor 必须自检）

重构完成后必须满足：

- 项目中不存在 ClasspathPluginLoader
- 项目中不存在 JarPluginLoader
- PluginLoader 仅有一个实现
- PluginLoader 不包含 SourceType 判断
- PluginLoader 不包含路径存在性判断
- PluginMetadata 包含 PluginSource
- Discoverer 构建 Metadata 时注入 source
- Resolver 不修改 source

------

# 六、架构目标达成标志

满足以下条件即为成功：

- 新增插件来源时，仅新增 PluginSource 实现
- Loader 代码无需修改
- Resolver 代码无需修改
- PluginManager 代码无需修改

------

# 七、禁止事项

本次重构不得：

- 引入新的顶层组件
- 改变装配规则
- 修改 PluginManager 外部 API
- 修改生命周期状态机
- 修改 SPI 注册中心结构

------

# 八、最终架构语义声明

重构完成后必须满足：

> 来源问题属于 Discoverer
> 冲突问题属于 Resolver
> 加载问题属于 Loader

Loader 不再知道插件来自哪里。

------

重构结束标准：

系统在保持原有功能完整的前提下，实现严格职责隔离，并支持未来新增任意插件来源而无需修改 Loader。
