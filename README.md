# Nexus Admin

## 项目概述

Nexus Admin 是一个面向后台管理场景的 **插件化业务拓展平台后端**。

平台旨在通过统一的抽象内核与动态插件机制，将认证、权限、路由、存储、AI等核心能力模块化，使业务功能与底层技术实现解耦。开发者可以像搭积木一样，通过编写或安装插件来灵活扩展平台能力，从而实现系统的快速定制与迭代。

## 设计理念

Nexus Admin 的核心设计思想是 **“内核稳定、插件扩展”**：

- **统一内核**：提供标准化的核心模型、调用上下文与能力抽象接口（SPI），构建稳定的运行时基座。
- **动态插件**：所有具体业务能力（如特定的认证方式、存储引擎、AI模型接入等）均以插件形式提供，支持运行时加载、启停与管理。
- **低耦合架构**：业务模块通过接口依赖，不与任何具体技术栈绑定，便于技术升级与替换。

## 核心特点

- **🔌 插件化扩展**：平台所有增强能力均通过插件动态接入，支持热部署与独立升级。
- **🧩 统一抽象层**：定义了认证、权限、存储、缓存、日志、AI等通用能力的标准接口，屏蔽实现细节。
- **🔄 运行时整合**：提供统一的 `CoreRuntime` 门面，聚合所有插件能力，对上层业务提供简洁一致的调用方式。
- **🧠 上下文感知**：内置 `CoreContext` 贯穿调用链路，天然支持多租户、链路追踪、会话管理等场景。

## 架构概览

平台采用分层与模块化设计：

1.  **核心模块**：定义领域模型与所有能力接口（SPI），提供运行时门面与上下文管理。
2.  **插件系统**：负责插件的描述、加载、生命周期管理，并作为SPI实现的注册中心。
3.  **基础设施模块**：提供与Spring Boot、Web框架等具体技术栈的默认集成与适配。
4.  **应用模块**：作为Spring Boot启动入口，自动装配核心组件并加载插件。
5.  **插件集合**：用于组织和管理各个独立的功能插件。

当应用启动时，平台会自动扫描指定目录下的插件，加载并初始化，将其实现的能力注册到内核中。业务代码通过统一的 `CoreRuntime` 即可调用这些能力，无需关心其具体来源。
